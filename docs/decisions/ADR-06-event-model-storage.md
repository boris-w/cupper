# ADR-06 事件模型与存储

- 状态：已采纳（2026-10-16，`gate/design`）
- 日期：2026-10-16
- 来源：SP-4a（宿主骨架）、SP-1（适配器实测）、ADR-04、对齐会架构师意见 1.3

## 背景

NFR-1、NFR-2 要求事件日志是会话的唯一事实来源，客户端断线重连后能补齐，不丢也不重复。

SP-1 实测发现，适配器提供的历史回放不能当作历史来源：
- 回放没有时间戳；
- Claude 压缩上下文之后，回放会丢掉早期内容；
- 回放里没有审批和用量信息；
- 会出现不属于任何 prompt 的更新。

SP-4a 已经用 Rust 验证了"连续 seq 加 SQLite WAL"这套模型，包括双客户端订阅、断线补齐、`kill -9` 后恢复、帧不超过上限。

## 决策

**存储**
- 存储引擎是 SQLite，开启 WAL 模式，只有宿主写入（单写者）。写入放在专门的存储线程上，或者批量写入，不在 async 的事件路径上同步调用。
- 持久性已定（设计评审修订，原写法为"M1 实测后再定"）：`synchronous=NORMAL` 加 `checkpoint_fullfsync`；写 `pending_external` 的那一批单独用 `FULL` 加 `fullfsync` 提交，之后才执行 git；断电后 seq 可能被重用，用 `data_epoch` 让客户端走快照（详细设计 5.2.8）。

**流**
- 有一条 index 流，内容包括项目、会话、状态、待处理的交互请求、已连接的客户端。
- 每个会话一条流。
- 同一条流内 seq 连续。宿主收到事件后先落盘，再下发给客户端。

**事件信封**
- 格式为 `{seq, from?, type, v, ts, cause, fallback?, data}`。
- 去掉 ADR-04 草案里的 `id` 字段，因为它和 (host_id, 流, seq) 重复。
- 每类事件都带 schema 版本号 `v`，有专门的升级器（NFR-10）。

**条目**
- 消息、思考、工具调用、计划、交互请求、错误、通知等，都按条目 ID upsert，生命周期是 started、delta、completed。
- 工具调用的 ID 用适配器给的 `toolCallId`。
- 命令输出和退出码由各适配器自己的提取层取出（SP-1）。拿不到时降级显示。

**回合由宿主推导**
- 回合以 `session/prompt` 的请求和响应为界。Codex 有 `threadStatus` 时优先采用。
- 不属于任何 prompt 的更新，归到"自发回合"里，例如 Claude 在后台命令结束后自动开启的回合。
- 回合结束时还没完成的工具调用，标为"已放弃"。
- 交互请求可以出现在回合之外。SP-4a 的骨架只允许在回合内出现，M1 需要放开。

**合并与大小阈值**
- 写入时合并：每个条目的第一个片段立即写入，之后每 40 ms 合并一次；条目结束时，或者要写入其他事件之前，先把缓存的片段写掉。
- 单个 delta 转义后不超过 16,000 字符，合并后不超过 32,000 字符。
- 内联内容超过 16,000 字符时改存为 blob。
- 标题截断到 1,000 字符。

  这些阈值对所有连接都一样（ADR-04）。

**快照与历史**
- 快照用一串事件来表达，由视图生成。客户端用和处理增量事件相同的 `apply` 来应用快照，只有一套代码。
- 用 `stream/snapshot` 分页下发快照。长会话只给最近若干个回合，更早的通过 `history/page` 向前翻页。
- 有一条性质测试保证：用快照重建出来的状态，等于原来的状态。

**内存里的视图**
- 冷启动时只加载 index。会话的视图按"检查点加日志"懒加载。
- 空闲会话的视图会被淘汰，控制内存。SP-4a 实测：6 个会话、每个 6,000 个条目时，宿主内存为 22.5 MiB。

**保留与检查点**
- 每个回合结束时写一个视图检查点。
- 日志设保留窗口。游标早于窗口时，用快照重新同步。
- 回合快照用到的 Git 对象存在单独的私有对象库里（ADR-10），和事件日志一起定保留上限，默认按会话保留，总容量超过上限时提示用户清理（NFR-11）。

**原始 ACP 帧**
- 原始帧存进单独一张表，带保留期（默认 14 天）。用途是：规范化逻辑修复后可以重算历史，以及排查问题和导出诊断包（NFR-12）。
- 只做结构化脱敏（账号字段、已知格式的凭据），不套用日志的长串规则，以便修复规范化逻辑后可以重算历史（设计评审修订，原写法为"脱敏要求和日志相同"）。

**历史的来源**
- 只有宿主自己的事件日志算数。
- 适配器的回放（`session/load`）只用来导入 CLI 里原有的会话（PS-5），导入的内容标为"可能不完整"。

**统一的错误事件**，覆盖三类情况：
- JSON-RPC 错误：-32000 认证失败、-32603 内部错误、1001 可以重启；
- 以文本形式出现的错误：`agent_message_chunk` 里是原始 JSON，同时 `threadStatus` 为 `systemError`；
- 会自动重试的上游错误：`_meta.codex.error` 且 `willRetry` 为真。

**规范化**
- cwd 一律存 realpath。
- `_auth/status_update` 只保存登录类型，不把邮箱和组织写入事件日志（SEC）。

**会话内搜索**
- 用 SQLite FTS5 实现，返回结果里的位置用 UTF-16 偏移（P1）。

## 后果

- **好处**：
  - 历史完整，带时间戳，不依赖适配器；
  - 多端看到的内容天然一致；
  - M3 可以逐条加密；
  - 骨架已经验证可行，冷启动 p95 只有 4.6 ms。
- **代价**：
  - 要维护事件的版本和升级器；
  - 原始帧和 Git 快照对象占磁盘空间，需要保留策略；
  - 视图需要淘汰机制。

## 设计评审修订（2026-10-16）

来源：设计评审会（`docs/meetings/2026-10-16-design-review/minutes.md`）、用户决定（`docs/meetings/2026-10-16-gate-design-decisions/minutes.md`）、详细设计 v0.7 的 5.13.2。本节是细化，不推翻上文；上文中被替换的写法已就地改正并注明。

- **回合快照**：每个回合结束时写回合快照，会话视图只保留最近 20 个回合，`history/page` 从回合快照读取。**回合快照写入后不可变**，事后的信息（例如晚到的工具输出）写成新事件。
- **存储**：blob 改为按内容寻址的文件；原始帧放在单独的 `raw.db`；写线程组提交，失败的操作用 savepoint 隔离。
- **工具调用 ID**：`toolCallId` 只作 upsert 键，协议里用宿主生成的 ID。
- **`threadStatus`**：有 prompt 在途时以 prompt 的响应为准，`threadStatus` 只用于显示运行状态和界定自发回合（Q11）。
- **索引流**不含已归档的会话，另加 `session/list_archived`；交互请求表记录所属的适配器实例（SEC-10）。

# 开发流程

```
① PRD → ② 技术设计 → ③ 任务拆分 → ④ 迭代开发 → ⑤ 验收发布 → ⑥ 复盘
```

| 阶段 | 产出 | 负责 | 闸门（用户确认） | tag |
|---|---|---|---|---|
| ① PRD | `docs/01-prd.md` | 编排者 + 用户；草稿需经产品-架构对齐会 | MVP 范围冻结 | `gate/prd` |
| ② 技术设计 | `docs/02-design.md`、`docs/decisions/` | 编排者（调研可派子 agent） | 方案和关键选型 | `gate/design` |
| ③ 任务拆分 | `docs/03-plan.md` | 编排者 | 任务顺序和粒度 | `gate/plan` |
| ④ 迭代开发 | 代码 + 测试 | 子 agent（每个任务独立 worktree） | 每个任务通过 review 后合并 | — |
| ⑤ 验收发布 | 发布记录 | 编排者 | 逐条对照 PRD 验收标准 | `release/vX.Y.Z` |
| ⑥ 复盘 | `docs/retro.md` | 编排者 + 用户 | 下一版输入 | — |

## PRD 的产出步骤（阶段 ①）

1. 需求访谈：编排者与用户沟通，必要时派调研任务（R 系列）补充事实。
2. 编排者根据访谈和调研结果起草 PRD。
3. 产品-架构对齐会：编排者与架构师子 agent 一起评审草稿，从产品分期和技术架构两方面确认需求能平滑演进（例如先做桌面端、再接入移动端时不需要推倒重来）。会上发现的约束和风险写回 PRD。
4. 用户评审 PRD，确认后打 `gate/prd`。

## 任务生命周期（阶段 ④）

1. 编排者从 `docs/03-plan.md` 选出依赖已满足的任务，写好 `brief.md` 并提交到 `main`，再派给子 agent（互不依赖的任务可以并行）。
2. 子 agent 在 `<type>/<任务ID>-<slug>` 分支的独立 worktree 中开发、自测、小步提交，最后把汇报全文作为回复返回；编排者把它存为 `report.md` 并提交。
3. 编排者 review diff 并跑测试，意见写入 `review.md`；不通过就打回给同一个子 agent 修改，每轮都记录。
4. 通过后 `git merge --no-ff` 合入 `main`，在 `docs/03-plan.md` 中把任务标记为完成，然后清理 worktree。

## 留痕体系

所有工作都要留下记录并提交到 git，包括讨论、会议、派发、汇报、review 和调研物料。

```
docs/
├── 00-process.md            流程与进度（本文件）
├── 01-prd.md / 02-design.md / 03-plan.md
├── decisions/               ADR：ADR-0001-<slug>.md
├── meetings/                会议：一次会议一个目录
│   └── YYYY-MM-DD-<slug>/
│       ├── minutes.md       会议记录
│       └── ...              物料：子 agent 原始发言、草稿、对比表等
├── tasks/                   派发卷宗：一个任务一个目录
│   └── <ID>-<slug>/         T = 开发任务（来自 03-plan.md），R = 调研任务
│       ├── brief.md         派发说明（编排者写，派发前提交）
│       ├── notes.md         工作笔记（子 agent，可选）
│       ├── report.md        汇报（子 agent 以回复形式返回，编排者存档）
│       ├── review.md        review 记录（编排者，含每轮意见）
│       └── ...              其他物料：调研原始数据、截图、基准结果等
└── templates/               以上各类文档的模板
```

### 什么时候开会、记什么

| 场合 | 会议类型 | 参与者 |
|---|---|---|
| 与用户的每段集中讨论（需求访谈、方案确认、闸门确认） | 需求访谈 / 同步会 / 验收会 | 用户、编排者 |
| 需要多视角的问题（技术选型、设计评审、疑难 bug） | 讨论会 / 设计评审 | 编排者 + 多个不同角色的子 agent |
| 每个里程碑结束 | 同步会 | 用户、编排者 |
| 每个阶段闸门 | 评审会，结论写入会议记录后再打 tag | 用户、编排者 |

与子 agent 开讨论会时：编排者先写好议程和背景材料；每个子 agent 以指定角色独立发表意见，原文存为会议目录下的 `<角色>.md`；需要交锋时把其他人的观点转给对方回应；最后由编排者整理成 `minutes.md`，交用户确认的事项标为"待用户确认"。

### 提交规则

- 记录类提交使用 `docs(<范围>): ...`，范围取 `meeting` / `task` / `prd` / `design` / `plan` / `adr`。
- 会议记录在会议结束后立即提交；需要用户确认的会议，确认后再更新一次记录。
- 任务的 brief 在派发前提交到 `main`，这样子 agent 的 worktree 里能读到。

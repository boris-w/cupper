1 概览

1.1 一句话定位

一个开源、自用优先的 macOS agent 工作台。用 Codex 的交互方式驱动 Claude Code 和 Codex，并能在 iPhone 上通过端到端加密的通道随时接管。（PRD 第 2 节）

  • 界面复刻 Codex 桌面版（ChatGPT 桌面 App 中的 Codex 视图，2026-10 基线）：布局和交互一致，视觉接近，不使用 OpenAI 的商标、图标和品牌素材（UI-6、Q3）。
  • 经 ACP 驱动用户本机已安装、已登录的官方 CLI；cupper 本身不提供登录（AG-1、AG-2）。
  • 会话由一个与界面分离的会话宿主进程持有；桌面界面、cupper-cli、将来的 iPhone 都是它的客户端（NFR-1）。
  • M3 加 iOS 端，经用户自建的中继远程接管会话，链路端到端加密（SEC-1、RL-1）。

6.2 自用阶段的安全须知（要点）

  • "本地鉴权较弱"是什么意思：自用构建和开发构建没有 Developer ID，宿主用界面拉起它时生成的一次性密钥认证界面（退化认证）。后果是界面崩溃或重启后连不上原来的宿主，需要重启宿主，运行中的回合会被中断。发布构建没有这个问题（PRD 第 10 节 Q22；设计 5.8.1）。
  • 只用自用构建处理真实项目：开发构建只用于开发和测试，不在真实项目上运行真实 agent（计划 1.10、第 6 节）。
  • 开启 agent 自带的沙箱：沙箱开着时 agent 执行的命令连不上宿主；不要给 Codex 的工作区模式打开网络访问，Claude Code 不要配置 allowUnixSockets。沙箱外的命令（批准过的、MCP、hooks）能连上，但只有只读权限，写操作和审批都要在桌面端确认（设计 5.8.7）。
  • 在 cupper 里提交会运行仓库的 hooks：风险与在终端里提交相同；本会话期间仓库的 hooks 或配置有变化时，提交前会提示。宿主自己自动执行的 git 不运行仓库配置里的任何程序（设计 5.2.10）。
  • 先确认信任再用：未经信任的项目，项目自带的 hooks、MCP 服务器、环境变量、apiKeyHelper 都不生效；信任之后配置又变了，最迟在下一个 prompt 之前发现并要求再次确认。回合进行中被改写的配置，CLI 可能在当前回合内就加载（待定 Q28）。
  • 低打扰档位（Claude 的 auto、acceptEdits，Codex 的 Auto review）由分类器代替你审批，切到这一档需要审批权限。
  • 不要因为 agent 的操作授予 Cupper 辅助功能权限：agent 触发的系统授权提示会显示成 Cupper；有了辅助功能权限，agent 能合成点击，替你点掉确认框。
  • 挡不住的：同一用户下、在沙箱外有明确恶意的进程（它可以改 agent 的权限配置和 cupper 的数据目录、杀掉宿主、对确认框做社会工程）。
  • 本机数据：会话记录以明文存在本机，依赖 FileVault（SEC-11）；回合快照可能复制了没被 gitignore 的密钥文件，可以在设置里清除快照对象。

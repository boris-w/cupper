## 1. 背景与问题

1. **最好用的 agent 工作台只服务一家 agent。** Codex 桌面客户端（现为 ChatGPT 桌面 App 中的 Codex 视图）把"并行跑多个会话 → 审批 → 审查 diff → 提交"做成了顺手的闭环，但它只能驱动 Codex。同时使用 Claude Code 的开发者，要么回到终端，要么在两套工具之间来回切换。（R01）
2. **离开电脑后，agent 就停在那里等审批。** 官方的移动端远程功能（Claude Code Remote Control、Codex Remote）都要经过厂商的中继，只有 TLS 加密，厂商能看到会话内容。第三方方案中做了端到端加密的只有少数几家，而且都有配对认证或推送明文方面的缺陷。目前没有一个产品同时做到"多 agent + 扎实的端到端加密"。（R03）
3. **开放协议已经可用。** ACP v1 已经稳定，Claude Code 和 Codex 都有官方组织维护的 ACP 适配器，第三方客户端可以用统一的方式驱动这两个 agent。（R02）

## 2. 产品定位

**一句话**：一个开源、自用优先的 macOS agent 工作台。用 Codex 的交互方式驱动 Claude Code 和 Codex，并能在 iPhone 上通过端到端加密的通道随时接管。

**目标用户**

- 首要：作者本人，即同时使用 Claude Code 和 Codex 的开发者。
- 次要：开源社区里有同样需求、愿意自己部署的开发者。

**目标**

| # | 目标 | 衡量方式 |
|---|---|---|
| G1 | 日常开发中替代 Codex App 和终端里的 Claude Code | 作者连续两周的日常开发主要在 cupper 中完成【默认】 |
| G2 | 离开电脑时，能在 iPhone 上处理审批、追加指令 | 离开电脑期间的审批都能在手机上完成，不需要回到电脑前 |
| G3 | 除用户自己的设备外，任何一方（包括中继服务器）都看不到会话内容 | 抓包和检查中继存储，确认只有路由信息和密文 |

**不做的事（非目标）**

- 不复刻 ChatGPT 的 Chat、Work、Sites 等非编码功能，只复刻 Codex 编码视图。（R01）
- 不做云端执行、云任务、SSH 远程主机。
- 不做账号、计费，不内置任何 Claude 或 ChatGPT 登录流程。（见第 8 节）
- 首期不做 Windows、Linux、Android、Web 客户端。
- 不做团队协作或多人共享会话。
- 不追求补齐 Codex 自家 harness 的专有能力（例如 Approve for me 的审查 agent、Goal、Memories）。某个 agent 本身提供这些能力时再接入。
- 不提供官方托管的中继或推送服务。

## 3. 核心概念

| 概念 | 说明 |
|---|---|
| Agent | 被驱动的编码 agent。首期只支持 Claude Code 和 Codex，使用用户本机已安装、已登录的官方 CLI |
| 项目 | 本机的一个代码文件夹 |
| 会话 | 某个项目下、与某一个 agent 的一段对话。创建时选定 agent，之后不能更换 |
| 回合 | 用户发一条消息，到 agent 停下来为止的这一段工作 |
| 审批 | agent 执行越界操作前向用户发起的请求，任何一台已配对的设备都可以处理 |
| 会话状态 | 空闲 / 运行中 / 需要处理 / 完成未读 / 出错。所有界面（侧边栏、通知、手机）用同一套状态（R01） |
| 已配对设备 | 经扫码配对、可以远程操作本机会话的 iPhone，可以在桌面端撤销 |

## 4. 关键使用场景

| # | 场景 |
|---|---|
| S1 并行开发 | 在项目 A 里同时开两个会话：用 Claude Code 修一个 bug，用 Codex 补测试。两个会话各自在独立的 worktree 里运行，互不干扰。侧边栏能看出哪个在运行、哪个在等我 |
| S2 审批 | agent 要执行越界命令时，消息流里出现审批卡片，按 Enter 批准、Esc 拒绝，可以选"本次"或"本会话都允许"。窗口不在前台时收到系统通知 |
| S3 审查到提交 | 回合结束后打开审查面板看 diff，在某行写评论让 agent 改；满意后按文件或 hunk 暂存，生成提交信息，提交并推送 |
| S4 运行中追加指令 | agent 还在工作时，我补充一句话：可以插进当前回合（Steer），也可以排到下一回合（Queue） |
| S5 离开工位 | 我在外面，iPhone 收到推送："项目 A / 修 bug 需要审批"。解锁后查看命令详情并批准，然后回到会话列表看进度 |
| S6 手机上追加指令 | 在手机上查看某个会话的实时输出，追加一条消息让它换个思路 |
| S7 首次配对 | 桌面端显示二维码，手机扫码完成配对，之后不需要再配对；手机丢了可以在桌面端撤销 |

## 5. 分期

| 里程碑 | 内容 | 退出标准 |
|---|---|---|
| **M1 桌面 MVP** | 第 6.1 节中的 P0 功能 | 作者能用它完成 S1–S4 的完整流程，Claude Code 和 Codex 都能用 |
| **M2 桌面完善** | 第 6.1 节中的 P1 功能 | 按需求迭代 |
| **M3 iOS MVP** | 配对、会话列表、实时输出、追加消息、审批、加密推送（第 6.2 节的 P0），以及中继 | S5–S7 跑通，并且满足第 6.3 节的全部安全要求 |
| **M4 iOS 增强** | 第 6.2 节中的 P1 功能 | 按需求迭代 |

**平滑演进要求**：M1 的桌面端必须按"移动端将作为第二个客户端接入"来构建，M3 接入时不改写桌面端的界面和会话逻辑。见第 7 节 NFR-1。

### 6.3 安全与隐私

| ID | 需求 | 优先级 |
|---|---|---|
| SEC-1 | 端到端加密：桌面端与手机之间的全部内容，包括会话标题、项目路径、主机名、命令和推送内容，中继都看不到。中继只能看到设备 ID 和密文 | P0 |
| SEC-2 | 配对时双向认证：二维码里放一次性、短时效的秘密，用它认证手机回传的应答，避免中继冒充（R03 发现 Happy #1503 就是这类问题） | P0 |
| SEC-3 | 每台设备一把独立密钥；在桌面端可以查看和撤销已配对设备；撤销后，被撤销的设备无法再解密新内容 | P0 |
| SEC-4 | 来自手机的审批和指令都带设备签名，桌面端执行前先校验 | P0 |
| SEC-5 | 客户端拒绝明文降级：一旦启用加密，任何时候都不接受未加密的连接 | P0 |
| SEC-6 | 默认不收集任何遥测数据 | P0 |
| SEC-7 | 文档明确说明加密覆盖的范围：中继能看到哪些元数据（IP、在线时段、消息大小和频率），以及 Apple 推送服务能看到什么 | P0 |

### 6.4 中继

| ID | 需求 | 优先级 |
|---|---|---|
| RL-1 | 中继是一个开源的单体服务，由用户自己部署（Docker 或单个可执行文件）；桌面端和手机都只需要发起出站连接 | P0（M3） |
| RL-2 | 中继只缓存最近一段时间的密文（默认 7 天），用于断线后补齐和推送拉取；完整历史以桌面端本地为准【默认】 | P0（M3） |
| RL-3 | 推送由中继直接发出，使用用户自己的 APNs 凭据（iOS App 由用户用自己的开发者账号构建） | P0（M3） |
| RL-4 | 手机与电脑在同一局域网时直连，不经过中继 | P2 |

## 7. 非功能需求

| ID | 需求 |
|---|---|
| NFR-1 平滑演进 | 会话、事件历史、审批、Git、worktree、终端等能力都放在一个与界面分离的"会话宿主"里。桌面界面从 M1 开始就作为它的一个客户端。M3 接入手机时，只增加一种传输和配对能力，不改写桌面界面和会话逻辑。**M1 验收要求**：除桌面窗口外，还能有第二个客户端（例如一个测试客户端）订阅同一个会话，看到一致的内容，并能处理审批 |
| NFR-2 断线续传 | 任何客户端断线重连后，都能从断点补齐，不丢消息，也不重复 |
| NFR-3 后台运行 | 关闭窗口不中断正在运行的会话（P1）；退出 App 时，如果有会话在运行，要先提示 |
| NFR-4 数据本地化 | 会话数据只存在用户本机，以及（M3 起）用户自建中继上的加密缓存 |
| NFR-5 版本可控 | 随 App 锁定经过验证的适配器版本；升级适配器要经过回归验证（R02：适配器几乎每天发版） |
| NFR-6 性能 | 流式输出不卡顿；一千条以上消息的长会话滚动流畅；冷启动到可用不超过 2 秒【默认】 |
| NFR-7 可降级 | ACP 标准未覆盖的能力（排队、Steer、运行状态、汇总 diff、worktree）由 cupper 自己实现；只能依赖 agent 私有扩展的能力，按能力探测后启用，不支持时降级（R02） |

## 8. 合规与约束

- **账号**：cupper 不内置任何 Claude 或 ChatGPT 的登录流程，只调用用户本机已安装、已登录的官方 CLI。同时支持用户通过环境变量自行配置 API key。（访谈 #2；R02 S11）
- **商标**：产品名、图标和宣传中不使用 "Claude Code"、"Codex"、OpenAI 或 Anthropic 的商标和品牌素材；README 不写"使用你的 Claude 订阅"之类的说法。
- **UI 复刻边界**：复刻布局、交互和信息架构；视觉素材（图标、插画、宠物等）自己制作。
- **开源许可证**：待定，在阶段 ② 用 ADR 决定。需要和依赖的许可证兼容，例如 Claude Agent SDK 受 Anthropic 商业条款约束。
- **大范围公开分发之前**：先向 Anthropic 确认第三方客户端调用用户本机 CLI 的政策边界。

## 9. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| ACP 适配器变化快，几乎每天发版，有过破坏性变更 | 功能随时可能失效 | 锁定版本，做兼容性回归测试（NFR-5） |
| ACP 缺少 Codex 风格 UI 需要的能力 | 部分功能做不到或体验不一致 | 由 cupper 的会话宿主补齐；按 agent 降级；Codex 是否改为直连 app-server，在阶段 ② 用 ADR 决定 |
| 适配器的已知缺陷（回放不完整、拒绝审批会结束整个回合等） | 历史和审批的体验受影响 | 历史以 cupper 自己的事件日志为准，不完全依赖 agent 回放；阶段 ② 做原型实测 |
| Codex 界面持续演进 | 复刻目标在移动 | 以 2026-10 的 Codex 视图（R01 加截图）为基线冻结 |
| 端到端加密方案存在设计或实现漏洞 | 安全承诺失效 | 设计阶段做专门评审，配对和加密使用成熟协议与库，不自己发明密码学方案 |

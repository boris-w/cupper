# MAN-S3：审查到提交

- 场景：PRD S3。回合结束后打开审查面板看 diff，在某行写评论让 agent 改；满意后按文件或 hunk 暂存，提交并推送。
- 对应需求：GT-1 至 GT-4，以及回合改动卡片（F3）。假 agent 的自动化版本是 E2E-S3（T171）。
- 共同约定见 [README.md](README.md) 第 4 节。每一步 Claude、Codex 各走一遍，结果分两列。可以接着用 MAN-S1 留下的 worktree 会话。

## 准备

- 一个 worktree 会话，分支可以推送到远端，例如 `s3-review-claude`、`s3-review-codex`，每种 agent 一个。
- 让 agent 做一个会改动两三个文件的小改动，等回合结束。

## 步骤

| # | 操作 | 预期与通过条件 | 依赖 |
|---|---|---|---|
| 1 | 回合结束后看消息流 | 最终回答之后出现回合改动卡片，显示改动的文件数和增删行数；点开跳到审查面板 | T132 |
| 2 | 打开审查面板（⌃⇧G），在"最近一回合"和"未暂存"两种范围之间切换 | 文件列表和 diff 与终端里 `git diff`（未暂存）一致；"最近一回合"只显示这个回合的改动（GT-1） | T130、T131（或 T139） |
| 3 | 在某个文件的一行上写行内评论，例如"这里换个名字"；再到输入框发"按评论改" | 评论作为附件出现在输入框里，随这条消息发给 agent；agent 按评论改了，审查面板随之更新（GT-2） | T130、T131 |
| 4 | 按 hunk 暂存一处，再按文件暂存另一个文件；然后取消暂存那一处 hunk | 每一步之后，终端里的 `git diff --cached` 都与面板一致（GT-3） | T121 |
| 5 | 还原一个 hunk | 先出现确认控件，确认后那处改动消失，终端里看也是如此 | T121 |
| 6 | 写提交信息并提交 | 按钮旁注明"将运行仓库的 hooks"。提交后终端 `git log -1` 是这次提交，内容只有暂存的部分 | T123 |
| 7 | 推送 | 远端出现这个分支和提交。如果推送失败（例如没有权限），显示错误和恢复指引，不丢失提交 | T123 |

## 收尾

- 在终端删掉远端的临时分支（`git push origin --delete <分支>`）和本地分支。
- 记录里写明推送到的是哪一种远端（例如"作者的私有仓库"），不写仓库地址。

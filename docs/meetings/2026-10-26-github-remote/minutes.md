# 建 GitHub 远端、CI 上 GitHub

- 日期：2026-10-26
- 类型：讨论会
- 参与者：用户、编排者
- 关联：计划 1.8、P-2、U-P1、R7、R12；T099、T189、T195、T197

## 议程

1. e2e 在本机跑时要占用桌面，CI 能不能放到 GitHub 上跑。
2. 仓库公开还是私有，CI 的费用。
3. 公开前要不要重写历史。
4. 有了远端以后怎么协作。

## 讨论要点

- **e2e 占用桌面**：用户问 e2e 是否必须控制桌面、CI 上能不能跑。编排者的答复：
  - `@focus` 用例需要窗口拿到真实焦点，GitHub 的 macOS runner 有图形会话，能跑；
  - 其余用例可以改成不激活窗口，用户已决定派 T195。
  - T189 在本机连跑 50 次 E2E-SEC-real-input 时，50 次里有 45 次期间有用户输入，本机很难找到"没人用机器"的时段。
- **费用**：用户问 GitHub 上的 `macos-15` 免不免费。
  - 公开仓库的标准 runner 免费、不限量；
  - 私有仓库每月 2,000 分钟免费额度，macOS 按 10 倍扣，约合 200 分钟；一次 `ci pr` 估计 40–60 macOS 分钟，按每天合并十来个任务算，一天约 $25–40。
- **用户先要私有仓库**：

  > 现在开始把ci放到真正的github上跑，你在我的github上创建一个私有的仓库，然后在那里面协作

  编排者列出费用后，用户改选公开仓库。
- **历史里的个人信息**（计划 1.8"以后建远端时"、R12）：编排者对全部历史（3,414 个对象、1,972 个提交）做了扫描。
  - 两份旧会议记录（`2026-10-16-prd-arch-alignment/architect.md`、`2026-10-16-tech-selection/architect.md`）的旧版本里有本机路径，10-19 的 5fef216 已改成仓库相对路径，现在的文件是干净的；
  - 全部提交的作者邮箱都是同一个，公开后就公开了；
  - 没有密钥、主机名、会话链接：命中的都是脱敏代码里的假样例，或者对 `/remote-control` 的说明文字。
  - 重写历史能去掉这两处，并把邮箱换成 noreply，代价是全部提交的 SHA 都变：卷宗里引用的 SHA、CI 摘要的文件名和它记录的提交都对不上，正在跑的 agent 的分支也要迁移。用户选择不重写。
- **协作方式**：用户选择每个任务一个 PR。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 建公开仓库 `boris-w/cupper`，CI 放到 GitHub Actions 上跑（替换 U-P1"先不建远端"） | 公开仓库的标准 runner 免费、不限量；e2e 不再占用作者的桌面；"没人用机器"的条件在 runner 上天然满足 |
| D2 | 不重写历史，直接公开 | 暴露的只有作者邮箱和两份旧文件里的用户名与目录结构；重写会让卷宗里全部 SHA 引用失效 |
| D3 | 每个任务一个 PR。编排者推任务分支、开 PR，GitHub CI 通过后用合并提交合入 main；子 agent 仍不 push | 合并历史的形状与 `--no-ff` 相同；推送权限只在编排者手里 |
| D4 | Actions 先关闭，T197 把 workflow 配好、在 GitHub 上跑通后再打开；在那之前合并照旧以本机 `ci pr --record` 为准 | 现有 workflow 一推 main 就会触发，但还没配好依赖，跑了只会失败 |
| D5 | 按 R12 设置：外部贡献者的工作流需要批准；workflow 默认只读；不用自托管 runner；没有密钥 | 公开仓库的 Actions 可能被外部贡献者利用 |
| D6 | T189 剩下的 E2E-SEC-real-input 50 次连跑，以及 T099 的 20 次连跑，都在 GitHub 的 macOS runner 上做 | 本机很难保证没人操作 |

## 讨论要点

- R06 静态读取了作者本机 ChatGPT 桌面 App（Codex 视图，26.1013）的界面资源，又测量了参考截图，整理出 `ui-spec.md`。第 6 节列了两类问题：设计里有 17 处估计需要更正，有 16 个元素设计里没写。其中几处和 PRD 的写法不一致：
  - 审批是替换输入框位置的请求面板，不是消息流里的卡片；
  - 行内评论作为附件进入输入框，没有单独的"发给 agent"按钮；
  - 跟进消息默认插进当前回合（Steer），⌘Enter 排到下一回合；
  - 中断回合是按两次 Esc。
- 编排者给用户看了 D03 的初稿（带界面的 PRD），也报告了 R06 的结论。用户的回复是：

  > 嗯，大体ui看着还行，反正你可以直接看我本地的codex客户端源码。你就参照100%复刻就好了

- 编排者说明了边界：读本机客户端的资源，是为了 100% 复刻它的布局、尺寸、配色、交互、文案结构和快捷键；代码由我们自己写。对方的源码、样式表、图标、字体、图片都不复制进仓库，因为 cupper 以 Apache-2.0 开源，复制会带来版权问题。这也是 PRD UI-6 原有的约定。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| F1 | **界面以作者本机安装的 Codex 客户端为准，100% 复刻**：布局、尺寸、配色（亮色和暗色）、圆角、字体与字号、动效、交互、文案结构、快捷键。资料来源是对本机 App 包的静态读取（R06 的方法），加上参考截图。PRD、设计与它不一致时，界面形态以 Codex 为准 | 用户决定 |
| F2 | **只复刻，不复制**：不把对方的代码、样式表、图标、图片、字体复制进仓库；字体用系统字体（Codex 本身也用系统字体）；不使用 OpenAI 的商标和品牌素材。以后的界面任务可以只读查看本机 App 包（不启动 App，不读用户数据），解出来的文件只放在临时目录 | 开源许可和版权；PRD UI-6 |
| F3 | **功能范围仍按 PRD 的里程碑**。Codex 里有、但属于 M1 范围之外的功能，界面形态照 Codex 做，交付时间不变。<br>**进 M1**：与 M1 已有功能直接相关的界面元素，包括：<br>- 运行中的转圈、未读蓝点、等待审批与需要输入的文字标签；<br>- 发送按钮的三种状态；<br>- 排队消息的预览、编辑、插话；<br>- 计划药丸"Step n / m"；<br>- 回合末尾的改动卡片；<br>- 审查面板的文件树和底部的整组操作；<br>- 窄窗口时的行为、半透明侧边栏、toast 的位置。<br>**仍是 P1（M2）**：<br>- 内置终端抽屉（UI-1）；<br>- 摘要卡片；<br>- 侧边栏搜索、Activity 视图、组织和排序菜单；<br>- Pinned 分组、不属于项目的 Chats 分组；<br>- ChatGPT 的全局导航栏不做。 | 复刻程度改的是界面形态，不改范围；范围改动要另行决定 |
| F4 | **PRD 升到 v1.3**：<br>- AP-1、AP-5：审批和提问改为替换输入框位置的请求面板；<br>- GT-2：行内评论作为附件进入输入框，随下一条消息发出；<br>- CP-6：跟进消息默认插话，⌘Enter 排队；agent 不支持或插话失败时转为排队；<br>- UI-4：快捷键按 Codex 的默认值，中断是按两次 Esc；<br>- UI-6：写明 F1、F2。 | 与 F1 一致 |
| F5 | **Claude 的插话**：按 F1，Claude 会话默认也插话。ADR-07 记录过 Claude 插话的副作用：当前的工具调用会被丢弃，正在跑的命令会被移到后台。所以设置里保留"跟进消息默认排队"的选项（Codex 也有这个设置） | 复刻 Codex 的交互；副作用由设置兜底 |
| F6 | **后续工作**：<br>- 设计和计划按 R06 与本决定修订，任务 D04，由架构师执行。修订后，审批改为请求面板这部分的安全落点（5.7.8 中"可见满 500 ms"、Enter 和 Esc、焦点等规则）交安全工程师确认。<br>- D03（带界面的 PRD）按 `ui-spec.md` 和本决定做保真修订。 | — |

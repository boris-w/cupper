# 请求面板的安全确认：安全工程师

## 结论：附条件可以

RP-1 至 RP-11、宿主核对数字键序号、两处有意保留的与 Codex 的差异，整体可以接替原先针对卡片的保护。数字键直接提交我接受，不需要退回方案。但有五处要补，见最后一节。其中第 1 条最要紧：用户停顿两秒以上之后，面板会自动获得焦点，现有规则在这种情况下有空隙。

## 逐条意见

**1. 能否接替原先的保护**

基本能。
- **打字途中被借用**：第 3 条（打字后 1 秒内的 Enter、Space、数字键不算）加上 RP-3（2 秒内打过字就不自动获得焦点），覆盖了"一边打字面板一边出现"的情况。
- **窗口刚激活时误按**：第 7 条的冷却，加上"导航、切换会话、通知点击都不把焦点移到面板上"，覆盖。
- **被注入的渲染内容诱导批准**：样式规则（RP-9）、按原文逐字显示并转义不可见字符、特权选项一律走原生确认框（RP-7），都保留了下来。
- **数字键证据**：宿主核对数字等于选项序号，比 Enter 更强，因为证据绑定到了具体的选项。

但有以下四个空隙：
- **(a) 停顿超过 2 秒后的第一下按键。** 焦点在输入框、2 秒没打字时，面板会抢走焦点，并预选"允许一次"。用户停下来看输出，然后回来接着打字：
  - 如果先打字母，第 3 条会拦下紧接着的 Enter；可面板随即提示"再按一次 Enter"，正是在引导用户（用户以为自己在发消息）去按第二下，于是批准了。
  - 如果第一下就是数字（新消息以"1 …"开头），或者是 ⌘Enter（输入框里 ⌘Enter 是"排队发送"，面板上却是"提交"，肌肉记忆在这里冲突），会直接提交。
- **(b) 导航键不清掉尚未用掉的输入。** 设计的本意只是"导航键不触发第 3 条"，并不需要保留旧的输入。按了方向键，说明前面那下 Enter 没有用来提交，应当作废。否则被注入的渲染进程可以拿 ↑↓ 之前那下 Enter 的证据去提交。
- **(c) 编号与序号的对应没写清楚。** RP-6 写"数字键跳过效果未知的选项"。如果界面上的编号也跳过它，显示的编号就不等于它在 `options` 里的序号，宿主会拒绝正常的按键；反过来，要是有人想"改正"成按显示编号核对，宿主的这道核对就失效了。
- **(d) 还原确认的默认焦点在"确认"上（RP-11）。** 当确认控件由审查文档的 `revert` 消息触发时，用户此刻可能正在审查文档里写评论。而按第 1 条，审查文档里的按键根本不会被主进程记录，第 3 条也就看不到这些打字；焦点被移到"确认"后，用户的下一下 Enter 就会被算作真实输入，执行还原。

**2. 数字键直接提交：接受。** 前提是补上 (a)(c) 两处。补完后剩下的风险是：用户闲着、输入框为空、面板已经自动获得焦点时，新消息的第一个字符恰好是数字。这和"第一下按 Enter"属于同一类风险，而 Enter 提交这条路径本来就接受了。数字键只能选中它对应的那个选项；其中特权选项仍然要经原生确认框。

另外，ui-spec 第 4.4 节只写了"选项带编号"和"Enter 批准、Esc 拒绝"，没有核实 Codex 的数字键是不是"选中即提交"。设计里"与 Codex 相同"这句应标为"未核实"，由 T106 核对。

**3. 两处有意保留的差异：理由成立。**
- **系统通知上不放"批准"按钮。** 除了 5.7.8 已经写的几条理由，还有一条：通知按钮的回调由宿主的 helper 处理，相当于开了一条不经过任何客户端 principal 的审批通道，绕过了先到先得、摘要核对和输入证据。何况 Codex 通知里的"本会话批准"在 cupper 属于特权操作，本来就必须走原生确认。
- **还原确认框不提供"不再询问"。** 成立。另外按 (d)，由审查文档触发的那一种还要再收紧。

**4. "拒绝并附一条消息"：没有越权问题。** 这段文字是用户自己输入的，作为用户消息发给 agent（`cause` 是 `pr_desktop`），这正是这个功能的本意。拒绝用的是不持久的拒绝选项，方向是安全的。需要注意三点：
- 只有拒绝成功之后，才发出这条消息。如果收到 `already_resolved`（例如已经在 CLI 那边批准了）或 `expired`，文字留在输入框里，并提示"已在别处处理"。否则用户会以为自己拒绝了，实际上命令已经执行。
- 跟进消息遵守"跟进消息默认排队"的设置和 agent 的插话能力（F5）。Claude 的插话会丢掉其他工具调用，或把正在运行的命令移到后台。
- 消息流里，这条用户消息要标明它附属于哪一次拒绝。

## 必须补的

1. **面板的焦点规则（落在 T083；e2e 用例 E2E-SEC-panel-arming 补场景，在 T092）。**
   - 输入框里有未发送的草稿时，面板不自动获得焦点；
   - 面板获得焦点后，只要收到打字键（在选项列表上没有意义的键），就撤销键盘操作，回到"按 Tab 或点击以处理请求"的状态；
   - "再按一次 Enter"的提示只用于窗口激活后的冷却期，不用于刚打过字的情况；
   - 面板获得焦点后的第一下 ⌘Enter，只把焦点留在面板上，不提交。
2. **导航键（落在 T077 的 inputGuard，UNIT-input-guard 加用例）。** 导航键不触发第 3 条，但会清掉尚未用掉的输入。
3. **编号（落在 T083 渲染，T031 宿主核对；UNIT-policy-matrix 和 E2E 都加用例）。** 面板上显示的编号一律等于选项在 `options` 里从 1 起的序号，特权和效果未知的选项也占编号。按效果未知选项的编号不起作用；按特权选项的编号走 `requestPrivileged`。不允许重新排序选项。
4. **还原确认（落在 T130、T131；E2E 在 T093）。** 由审查文档消息触发的还原确认，不自动获得焦点，必须点击或按 Tab；同一时间只显示一个。由主文档按钮点击触发时，焦点可以按 Codex 放在"确认"上。
5. **"拒绝并附一条消息"（落在 T083，插话路径在 T140；IT 或 E2E 在 T093）。** 先等拒绝成功再发送；遵守默认排队的设置和插话能力；失败时文字留在输入框里。
6. **其他。**
   - T150 加一个单元测试，断言系统通知没有任何操作按钮；
   - Q41 写明"数字键选中即提交"未经核实，交 T106 核对；
   - MAN-keyboard 已经包含数字键，保留。

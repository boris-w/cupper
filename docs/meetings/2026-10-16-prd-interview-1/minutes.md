## 讨论要点

### 1. 初始需求

用户提出：

> 1. 复刻一个 codex ui 的桌面 agent 客户端，关键点是 codex ui 复刻，使用 acp 协议，初期只用支持 claude code 和 codex
> 2. 开发移动端，支持端到端加密，通过移动端来操作客户端

编排者的初步理解：

- **桌面客户端**：界面和交互复刻 OpenAI Codex 桌面 App。底层通过 ACP（Agent Client Protocol，Zed 主导的开放协议，客户端用 JSON-RPC 驱动 agent 进程）接入 agent。首批支持 Claude Code 和 Codex，目前两者都需要通过 ACP 适配器接入。
- **移动端**：远程查看和操作桌面客户端上的 agent 会话。中间链路做端到端加密，即使经过中继服务器，中继也看不到内容。
- **差异化价值（待确认）**：Codex 风格的体验，同时支持多个 agent，并且能在手机上接管。

### 2. 平滑演进的要求

用户补充：

> 找到平滑的实现方式，可以写 prd 的时候和架构师开会，从产品和技术架构上平滑的支持

编排者的理解：桌面端和移动端不要做成两套割裂的东西。PRD 阶段就要和架构师一起确认，产品分期和技术架构能够平滑演进：先做桌面端，再接入移动端时不需要推倒重来。

### 3. 需要先查清的事实

以下三点会直接影响 PRD 的范围和分期，编排者决定先派调研：

| 问题 | 调研任务 |
|---|---|
| Codex UI 有哪些功能、长什么样、怎么交互，复刻范围怎么划 | R01 |
| ACP 和两个适配器现在能提供哪些能力；复刻 Codex UI 时，哪些功能有协议支撑，哪些要自己补 | R02 |
| 移动端远程操控和端到端加密有哪些先例，有哪些架构选项和代价 | R03 |

每份调研报告都要包含"对架构的启示"一节，作为产品-架构对齐会的输入。

### 4. 待澄清问题

已发给用户，等待回答。每个问题附有编排者的建议默认值。

1. 定位：给自己用、开源，还是做成商业产品？
2. 差异化：为什么不直接用 Codex App 或现有方案（如 Happy）？最想要的差异点是什么？
3. "Codex UI" 指哪一个形态？复刻到什么程度？
4. 平台：桌面端支持哪些系统，移动端做 iOS 还是 Android？
5. 移动端第一版要能做哪些操作？
6. 连接方式：能否接受部署一个中继服务器（自托管）？
7. 账号：是否直接复用本机已登录的 Claude Code 和 Codex？
8. 分期和节奏：桌面端和移动端是否分两期？有没有时间节点？做到什么程度算成功？

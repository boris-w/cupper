## 讨论要点

编排者列出 10 项，每项附了建议，并说明"全部同意就回'按建议'，只想改其中几条就回编号加意见"。用户的回复是：

> 让你

编排者理解为"交给编排者决定"，于是 10 项都按建议定下来，并在回复里说明了这个理解，用户可以随时推翻任何一项。

Q5 的建议原本是"用你控制的域名或 GitHub 账号"，需要编排者给出具体的值。如果用用户的 GitHub 用户名或个人域名，就会把个人信息写进开源仓库，违反项目的隐私约定。所以编排者改用一个中性的前缀。真正把签名绑定到用户身上的是 Team ID，签名要求里本来就有，bundle id 只是标识，用不用自己控制的域名，在安全上没有区别。

# 产品-架构对齐会：议程

- 日期：2026-10-16
- 类型：设计评审（PRD 阶段的产品-架构对齐会）
- 参与者：编排者（主持，代表产品）、架构师（子 agent）
- 关联：阶段 ①；PRD v0.1（提交 `8eed5a1`）

## 目的

评审 PRD v0.1，确认产品分期和技术架构能平滑演进：先做 macOS 桌面端（M1、M2），再接入 iOS 和中继（M3、M4）时，不需要推倒重来。会上发现的约束、风险和修改建议写回 PRD，之后再交用户评审。

## 输入材料

- `docs/01-prd.md`（v0.1）
- `docs/tasks/R01-codex-ui-teardown/report.md`：Codex UI 拆解，尤其是第十三节功能清单、第十四节对架构的启示
- `docs/tasks/R02-acp-adapters/report.md`：ACP 能力矩阵、缺口、对架构的启示
- `docs/tasks/R03-mobile-e2ee-remote/report.md`：连接与加密方案、对架构的启示
- `docs/meetings/2026-10-16-prd-interview-2/`：用户决策和截图笔记

## 议题

1. **平滑演进**：NFR-1 是否足以保证 M1 到 M3 不返工？M1 中哪些东西必须一次做对，哪些可以放心推迟？
2. **架构骨架**（概念层面，不做最终技术选型）：有哪些组件、组件之间的边界和协议，以及 PRD 中的每一类能力分别落在哪个组件上。
3. **可行性与范围**：结合 ACP 和适配器的现状，哪些需求做不到、代价过高或者有隐藏前提？M1 的 P0 范围是否合理，应该挪动哪些项？
4. **遗漏**：PRD 缺了哪些需求或非功能需求？例如会话宿主的生命周期、崩溃恢复、升级与数据迁移、一台手机对多台 Mac。
5. **阶段 ② 的输入**：需要用 ADR 决定的问题清单，以及需要先做原型实测（spike）的问题。
6. **对 PRD 的具体修改建议**：逐条列出，引用需求 ID。

## 对再确认点的表态

- **(a) Trusted Types：接受，附条件。**
  - **主文档放行 `style-src 'unsafe-inline'`：接受。** 条件是 agent 给出的字符串不能进入 `<style>` 的文本、`insertRule` 或 CSS 自定义属性。例如 ANSI 颜色只能映射到固定的 class。否则 CSS 注入可以伪装或遮挡审批卡片上的按钮。用一条 ESLint 规则约束。
  - **审查文档：** 这里没有 Trusted Types，样式又放行了 inline，严格的 `script-src` 只挡得住脚本，挡不住标记和样式注入。在审查场景里，这个风险很具体：文件内容里只要有一段没转义的 `<style>`，就能把某些行藏起来，用户审查的就不是真实的 diff。需要三条：
    - (i) 加金样例：文件内容、文件名、行内评论里出现 `<style>`、`<img>`、`<a>`、`<base>`、`<link>`、`<meta>` 时，都按文本显示，DOM 里不能出现这些元素。
    - (ii) `app` 协议注册为 standard 和 secure；测试断言两个文档的 origin 不同，并且 iframe 访问 `parent.document` 会抛错。
    - (iii) 只接收创建时那个 MessagePort 上的消息，并按 schema 校验。`git/revert` 会丢掉用户的改动，只能由主文档里的控件，或主进程记录到的真实输入触发，不能凭 iframe 的一条消息就执行。
  - 后备方案（只用 `DiffHunksRenderer` 生成 HAST）更安全。Q29 的验证不通过时，直接改用它。
- **安全 #6：接受"只能显示到 agent 透出的程度"。** 最低要求：
  - 确认框逐字显示选项原文。Claude 的 Bash 选项原文里本来就带着命令前缀。
  - 宿主拿不到具体规则或写入位置时，明确写出"具体规则和写入位置由 agent 决定，以原文为准"，不能留空。
  - 从原文或 `rawInput` 里解析不出前缀时，提示"可能放行更宽的范围"。
  - 同时按 Q7 向上游反馈，请适配器在 `_meta` 里透出规则和写入位置。
- **经计划确认切到 auto 时仍走原生确认：同意。** 这比模式选择器更严，与 `allow_always` 类选项的处理一致。不需要为了两条路径一致而把它放宽。

## 对其他统一方案的意见

- **(c) 真实输入：整体接受，补四点。** 其中第 2、3 点会影响契约。
  1. "打字途中借用输入"仍然防不住：Space 在白名单里，而打字时空格最频繁；Enter 也用来发送消息。建议：前 1 秒内按过打字键时，紧接着的 Enter 或 Space 不记作真实输入（⌘Enter 除外）；另外，出方向的任何一条命令都会用掉尚未消耗的输入。
  2. 宿主对 window 角色的 `respond` 必须要求带 `input` 参数，缺了就拒绝，不能因为缺参数而跳过检查。
  3. "同一个 `command_id` 重发时不要求新的输入"，只适用于上次转发后没有收到宿主任何响应的情况（连接断了）。收到任何响应后都要删掉记录，包括 `too_early` 这样的错误。
  4. `requestPrivileged` 被取消后的冷却时间，建议从固定的 2 秒改为逐次加长：2 s、10 s、60 s。
- **(d3) dev_key 双向证明：方向对，但没有绑定信道，可以被中继。**
  - 攻击路径：
    1. 攻击者先连上真宿主，拿到真宿主的 nonce；
    2. 删掉套接字路径，换上自己的假宿主；UI 重连时，假宿主发出同一个 nonce；
    3. 攻击者把 UI 给出的证明转交真宿主，再把真宿主返回的 `host_proof` 转回 UI。

    结果是双方都校验通过，攻击者成了中间人，可以往 control 连接里注入命令。
  - 修法：计算证明时加入方向标签、双方的 nonce，以及各自在套接字上看到的对端 pid，例如 `HMAC(key, "c2h" | h_nonce | c_nonce | 宿主看到的客户端 pid)`，反方向用 `"h2c"`。被中继时，宿主看到的是攻击者的 pid，与 UI 计算时用的不一致，校验就会失败。
  - 字段的形状不变，但这属于第 1 组契约，**必须在冻结前定下来**。退化模式本来就弱，这一条的价值在于让 e2e 里的"假宿主"用例名副其实。
- **(b) 晚到输出：没有新的安全问题。** 取消时立即标 `may_still_run`，满足我的要求。小建议：当前回合里有 `late_tool_output` 时，这个回合的 `last_turn` diff 注明"包含取消后仍在运行的命令造成的改动"，免得用户把这些改动算到本回合的 prompt 头上。
- **U-R2：同意。** 手机不能放宽到 elevated，已经处在 elevated 的会话可以照常使用。补一条：手机新建会话（MB-9）时，如果 agent 的默认档位是 elevated，也算"放宽"，按安全 #3 的条件处理。
- **更正我第一轮对 #9 的建议**：`CLAUDE_CONFIG_DIR` 和 `CODEX_HOME` 不能简单剔除。用户自定义了配置目录时，剔除后 CLI 会找不到登录态（AG-6）；U-R4 的隔离运行也要靠这两个变量。正确做法是：
  - 这两个变量不能经 `env_passthrough` 名单传入；
  - 改由宿主从登录 shell 读取，校验后自己设置：必须是绝对路径、属主是当前用户、不在任何工作区内；
  - test-harness 构建可以经 `--test-config` 覆盖。
- **U-R4**：复制凭据之前，在 Q30 里一并核实：
  - OAuth 的刷新令牌会不会轮换。如果会，在副本里刷新可能让用户原来的登录失效。
  - 临时目录放在每个用户自己的临时目录下，权限 0700，用完即删。
  - 录制和报告都要经过 `tools/sanitize` 和测试 #25 的扫描。
- **#13**：在 Info.plist 里不写用途说明，对自动化这类权限有用（`NSAppleEventsUsageDescription`）。但辅助功能没有对应的用途说明键，提示照样会弹（未核实，凭记忆）。所以真正的缓解是 SP-10 的 disclaim。在它落地之前，只能靠安全边界说明里的警示，M1b 发布前必须写进去。

   - 理由：可以被中继，见上文的攻击路径。
   - 最低要求：加方向标签和对端 pid，在契约冻结前写进 5.3.2 和 5.8.1。

   - 最低要求：上文 (i) 和 (iii) 两条。

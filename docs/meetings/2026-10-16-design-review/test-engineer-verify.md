## 修订引入的新问题

1. **racy 用例要用固定时间戳构造，不能靠真实时钟碰。**
   - 问题：`notes.md` 的 12 次实验，结果依赖"改写和复制是否落在同一秒"。CI 上换了机器负载或 git 版本，可能测不出问题：Apple Git 与其他构建对纳秒时间戳的处理不同，未核实。
   - 建议：
     - 测试显式设置被改文件和 index 文件的 mtime（同一秒、大小不变）来构造 racy 状态，断言快照里是新内容；
     - 另加一个单元断言：复制出的临时 index 的 mtime 等于原文件的 mtime。
2. **测量闸门和 SP-6 缺两个负载工具。**
   - 问题一：闸门的负载按"每条会话流每秒 25 帧、约 2 KB"定义，但假 agent 的 `flood` 是全速输出、不限速，产生不了这个负载。
   - 问题二：5.9.7 的夹具和 5.9.6 冷启动的数据集（200 个会话、1,000 条消息）都写着"用宿主的测试钩子灌入"，但 5.9.9 的注入点表和 `test/*` 方法里都没有这个钩子。
   - 建议：补一个限速命令（如 `flood_rate <每秒片段数> <秒> <长度>`），或者补一个按速率产生合成事件的宿主钩子；再补 `test/seed` 或离线的数据库生成工具。
3. **SP-6 有几个场景还判不了。**
   - 场景 8：没写怎样造出"完全遮挡"，也没有前置断言。建议由主进程用一个不透明窗口盖住，测量前先断言 `document.visibilityState === 'hidden'`。runner 虚拟机上的遮挡检测是否可靠，未核实。
   - 场景 1："冷"和"热"没有定义（宿主是否在运行、是否清过文件缓存）。
   - 场景 2：要测"输入延迟"，但 5.9.6 没有对应的预算。
   - 场景 4："视口是否跳动"要给数值阈值，例如锚点元素的位移不超过 1 px。
4. **`protocol` 作业放在 ubuntu 上，要先确认 `xtask` 能在 Linux 上编译。**
   - 问题：`pnpm gen` 会运行 `cargo xtask schema`。而 `xtask` 里还有 `compat`（要驱动宿主和 CLI）、`host-bundle`、`runtime-pack`。如果它依赖 `cupper-cli` 或 `cupper-sys`，在 ubuntu 上编译会失败。
   - 建议：在 5.1.3 写明 schema 导出不依赖 `cupper-sys`，例如把 schema 导出放在 `cupper-protocol` 自己的 bin 里，或者把 `compat` 拆成单独的 crate。
5. **5.9.10 基本能直接拆成任务，但有一处引用不成立。**
   - 能拆：追溯矩阵和 K 清单都引用了具体编号，并标了在哪个套件里跑。
   - 不成立的一处：MS-2 引用的 GOLD-A-claude-s02d 里没有思考帧。我检查了 SP-1 的 18 份 Claude 录制，`agent_thought_chunk` 一次都没有出现。所以 M1a（只有 Claude）的 MS-2 实际上没有正向用例。建议：
     - 改引用"IT + claude 形态的 `think`"；
     - 真实的 Claude 思考流录制，留给兼容矩阵用 sonnet 或 opus 补。
   - 另建议 CI 加一道检查：文档里引用的每个编号，要么对应一个同名测试，要么标明所属里程碑尚未实现，防止追溯矩阵与代码脱节。

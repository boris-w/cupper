## 修订引入的新问题

1. **重要：信任扫描不跟随符号链接，合并前要补上。** 5.2.6 写的是"不跟随符号链接，只记录它指向的路径"。可是 CLI 加载配置时会跟随链接，于是：
   - 当 `.claude/settings.json`、`.mcp.json` 或整个 `.claude/` 是指向工作区外的链接时，findings 里看不到链接目标中的 hooks，确认框显示"干净"，用户会信任一个其实带 hooks 的项目；
   - 信任之后，只要改写链接目标（例如放在沙箱可写的 `$TMPDIR` 下），摘要也不变，项目不会转成 `stale`。

   **修法**：
   - 符号链接按解析后的目标内容计入摘要和 findings；
   - 目标在工作区外时醒目标出，或者干脆不允许信任这个项目；
   - 顺带补一项待核实：如果项目目录只是某个仓库的子目录，CLI 可能还会从仓库根目录或中间各级目录加载项目配置（Codex 的 `.codex/` 是分层加载的）。扫描范围应覆盖从工作区到 git 根目录的整条路径。
2. **重要：git 和 git-lfs 按登录 shell 的 PATH 查找。** 见 5.2.10 的 LFS 例外和"调用约定"。如果 PATH 里有相对路径（`.`、`node_modules/.bin`），或者有指向某个项目目录的条目，宿主就会执行 agent 放在工作区里的同名程序，绕过三档防护。

   **修法**：
   - 宿主启动时把 git 和 git-lfs 解析成绝对路径，只从 PATH 里那些不在任何项目、工作区、临时目录下的绝对路径条目中查找；
   - 快照档配置里的 LFS 过滤器写成绝对路径；
   - git 子进程的 PATH 也去掉上述条目，工作目录设为 cupper 自己的目录。
3. **建议：`filter_unsupported` 的检测不完整。** 检测是在快照档里执行 `check-attr`，而快照档不读仓库的 `info/attributes`。只在 `info/attributes` 里声明了过滤器的路径不会被标出来，这时 hunk 操作照常提供，暂存会把工作区里的明文写进 index。

   **修法**：
   - 检测覆盖全部属性来源；
   - 仓库档的 `git/stage` 执行前，再用 `check-attr` 核对一次（这条命令不执行程序），发现白名单以外的过滤器就拒绝；
   - 这类路径的快照里存的是明文，而 M1 不回收快照对象，建议改为只存占位和哈希。
4. **建议：越权档位在回合中途出现时，当前回合不受控。** `config_unconfirmed` 选择暂停可以接受，不悄悄改用户的模式也符合 PRD。但暂停只拦住后面的 prompt：如果回合进行中收到 `ConfigChanged`，发现档位越权，当前回合仍会在越权档位下跑完。建议这时先中断当前回合，或者把档位改回原值，再进入 `config_unconfirmed`。
5. **扫描范围内没有文件的项目直接记为已信任（`auto_empty`）：没有问题。** 空摘要也是一个摘要：之后出现任何文件，摘要就会变化、转成 `stale`，而每次发送 prompt 前都会重新扫描。
6. **快照档的范围扩大到 diff、status 和 `@` 文件列表：没有新问题。** 反而缩小了执行仓库程序的范围；写操作仍然走仓库档，并以 `diff_token` 为前提。

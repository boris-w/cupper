## 决策

以下是编排者的裁定。修订时以本表为准；本表没有提到的意见，按 `architect-response.md` 和三份 `*-confirm.md` 中的"附条件"处理。

| # | 决策 | 理由 |
|---|---|---|
| D1 | **Q1 定案**：主进程持有一条 control 连接，每个窗口另有一条数据连接。同时补齐四项：<br>- 数据连接的生命周期（桌面 #1）；<br>- 每条连接只接受一次 `initialize`，角色确定后不可变，window 连接的 `initialize` 由主进程代发（安全 #4）；<br>- 主进程转发的测量前移到 M1a，作为闸门；<br>- 闸门的判定负载按订阅上限定义：索引流 + 4 条会话流 + 5 MB blob + 5,000 个事件的重新同步，按线路上的帧数和字节数计量，消费端用真实的渲染进程，可见和遮挡两种状态各测一次。6 条流的结果只作压力报告 | 三位评审都同意。负载按桌面确认意见收窄，避免为碰不到的负载去改 ADR-05 |
| D2 | **Q4 定案**：codex-acp 随包分发，附以下条件：<br>- CI 按 SRI 校验；<br>- 清单记录 sha-256；<br>- 附带内联依赖的许可证声明；<br>- 每晚执行 `runtime-pack --verify`；<br>- test-harness 构建里 registry 地址可以注入 | 三方一致 |
| D3 | **Q11 定案**：有 prompt 在途时，以 prompt 的响应为准。<br>`threadStatus` 只用于显示状态和界定自发回合，它变成 idle 也不会让挂着的交互请求失效。<br>界面只看 `SessionStatus`，"需要处理"只由 cupper 自己的待处理请求决定 | 三方一致 |
| D4 | **Q14 定案**：回合快照写入后不可变。<br>- 取消时：如果 agent 的能力描述 `interrupt_stops_commands` 为 false，还在运行的命令记为 `abandoned` 加 `may_still_run`。<br>- 输出晚到时：在当前回合（没有当前回合就开一个 autonomous 回合）新建一个 `late_tool_output` 条目，原条目不改，视图用反向索引在原条目旁显示链接。<br>- 显示：这个条目显示在回合折叠之外，不并入活动组，不参与"最终回答"的判定（桌面确认）。<br>- 金样例按测试确认的三层断言：<br>  - A 层只断言晚到的帧被提取出来，并带着原 `toolCallId`；<br>  - 回合结构由宿主集成测试加假 agent 断言；<br>  - B 层等 M1b 用宿主重新录制后再补。<br>- 另加两项检查：不变式"回合快照写入后，日志里不再出现指向该回合的事件"；`late_by_ref` 纳入差分测试。<br>- 有晚到输出的回合，`last_turn` diff 要注明"包含取消后仍在运行的命令造成的改动"（安全建议） | 三方的诉求（让用户知道副作用、不丢内容、历史可测）都能满足，也不破坏回合快照 |
| D5 | **Q15 关闭**，持久性配置如下：<br>- 默认 `synchronous=NORMAL`，并开启 `checkpoint_fullfsync`；<br>- 写 `pending_external` 的那一批，单独用 `FULL` 加 `fullfsync` 提交，之后才执行 git；<br>- 断电后 seq 可能被重用，为此引入 `data_epoch`，判定依据是启动会话的 UUID 加上"上次是否异常退出"。两个输入都可以注入，测试用例按测试确认中列的 4 条写 | 按 SQLite 和 macOS 的文档就能决定。VM 断电实验在 CI 上做不了，也区分不出这些配置 |
| D6 | **Trusted Types 采用第三种方案**：<br>- 主文档禁止 `default` 策略，只保留具名策略 `cupper-worker`；<br>- 主文档放行 `style-src 'unsafe-inline'`，但 agent 给出的字符串不能进入 `<style>`、`insertRule` 或 CSS 自定义属性（用 ESLint 约束）；<br>- 审查用的 diff 视图放进单独源的 iframe，原样使用 @pierre/diffs。<br>**采纳安全工程师的三条最低要求**：<br>- (i) 注入金样例：文件内容、文件名、评论里出现的 `<style>`、`<img>`、`<a>`、`<base>`、`<link>`、`<meta>` 一律按文本显示；<br>- (ii) `app` 协议注册为 standard 和 secure，测试断言两个文档跨源隔离；<br>- (iii) 只接收创建时的那个 MessagePort 的消息，并按 schema 校验。`git/revert` 等破坏性操作只能由主文档的控件或主进程记录的真实输入触发。<br>桌面确认列出的 8 点（进程与内存、焦点与快捷键、iframe 内的输入不能计入主框架的真实输入、主题同步、无状态视图与版本化消息协议、剪贴板、滚动联动、复刻度）并入 Q29 的验证和 5.7.5。<br>Q29 不通过时，直接改用 `DiffHunksRenderer` 后备方案 | 主文档保持严格；审查面板保住复刻度。注入测试补上了"严格的 `script-src` 挡不住样式注入"这个缺口 |
| D7 | **真实输入规则**以 `architect-response.md` 的 (c) 为基础，补充以下几点：<br>- 安全确认的 4 点：<br>  - 1 秒内按过打字键时，紧接着的 Enter 或 Space 不算真实输入，任何出方向命令都会用掉尚未消耗的输入；<br>  - window 角色发来的 `respond` 缺少 `input` 参数时一律拒绝；<br>  - 同一个 `command_id` 免输入重发，只限"上次转发后没有收到任何响应"的情况；<br>  - `requestPrivileged` 被取消后，冷却时间逐次加长：2 s、10 s、60 s。<br>- 桌面确认：冷却期间按 Enter，卡片提示"请再按一次"。<br>- 测试确认：<br>  - 每次升级 Electron 大版本，都用实体键盘人工确认一遍；<br>  - 加一个自动用例，断言输入证据来自 `before-input-event`；<br>  - Q26 复测时，确认 `input-event` 在运行时是否带键码。<br>- 桌面确认：inputGuard 只记录主框架获得焦点时的输入（与 D6 相关） | 三方的补充互不冲突，合起来是一套完整规则 |
| D8 | **宿主自动调用 git 的安全档位**，以架构师方案为基础，采纳安全工程师的两条最低要求：<br>- ① **每次**自动档调用前都读取配置、计算覆盖项；调用后再比对一次指纹，指纹变了就丢弃结果并写 notice；<br>- ② `--show-origin` 显示配置来源位于工作区或其他 agent 可写的位置时，按 `unsafe_repo_config` 处理，跳过快照并提示。<br>另外，用 `-c` 覆盖后 git 报错（例如 `filter.*.required`）时，一律跳过快照，不去掉覆盖重试。<br>**修订时还要评估一个方案**：快照改用 cupper 自己的 GIT_DIR，用 alternates 指向仓库的对象，只拷贝白名单里的无害键和 `info/exclude`。这是把"列举危险键"改成"只放行安全键"。如果用 SP-5 的用例验证可行，快照路径就采用它 | 按"每个回合读一次配置"实现时，agent 在回合中写进去的配置会在回合结束的快照里被执行。白名单方式更稳，但要先验证它和 SP-5 的快照方案兼容 |
| D9 | **项目信任**（安全 #2）：方案按架构师所写，采纳安全确认的四个条件：<br>- 信任摘要按全部相关文件的完整内容计算；<br>- 每次发送 prompt 之前都重新扫描；<br>- 兼容剧本扩大断言范围：hooks、MCP、env、apiKeyHelper 都不生效；<br>- 每次探测前把探测目录重建为空目录。<br>是否增加这一步，等用户决定（U-R1） | 产品层面多了一步，需要用户决定；技术方案已经收敛 |
| D10 | **风险档位**（安全 #3）：档位表和权限矩阵的拆行按架构师所写。补一条规则：会话的默认档位来自用户自己的 CLI 配置时，视为由创建会话的 principal 设定。<br>所以只有 write 权限的 CLI（以及 M3 的手机）新建会话时，如果默认档位是 elevated，要么按 `config_unconfirmed` 处理，要么降到 normal | 补上默认值这个没有定义的情况（Codex 的默认值常常就是 `agent`） |
| D11 | **dev_key 双向证明加信道绑定**：证明里加入方向标签、双方的 nonce，以及各自在套接字上看到的对端 pid，例如宿主计算 `HMAC(key, "c2h" \| h_nonce \| c_nonce \| 宿主看到的客户端 pid)`，反方向用 `"h2c"`。属于第 1 组契约，冻结前写进 5.3.2 和 5.8.1 | 原方案可以被中继，中继者会成为中间人。加 pid 后，中继时双方计算用的 pid 对不上，校验失败 |
| D12 | **时钟抽象**（测试 #1）：按架构师方案，补三点规格：<br>- `test/clock_advance` 要等到期的定时器全部触发、由此产生的动作执行并落盘之后才返回；<br>- 禁用清单补上 `elapsed`、`tokio::time::Instant::now`、`std::thread::sleep`，UUIDv7 也经 Clock 或可注入的 ID 生成器生成；<br>- 测试里不关闭攒批，改成"攒够数量或队列为空就刷出"，以覆盖组提交 | 测试确认的条件 |

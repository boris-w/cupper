## 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | **CI 改在本机执行**（U-P1）。所有作业经 `cargo xtask ci <作业>`，在干净的 worktree 里运行。规则如下：<br>- 入库的只有结构化摘要和逐编号的结果清单，原始日志放 `.private/`；<br>- 有机器级的锁，同一时间只跑一个作业；<br>- 截图基线固定渲染因素；<br>- M1a 的退出条件是连跑 20 次，再加 5 次降速变体；<br>- macOS 14、15 上的对端校验，以及 CI 负载下的稳定性，在里程碑退出时列为缺口，由用户确认。<br>workflow 文件照写，暂不启用 | 用户先自用，不公开；私有仓库托管 macOS 作业的分钟数按 10 倍计费 |
| D2 | **契约冻结 T016 排在测量闸门 T078 之后**（P-1） | 测量闸门不通过时启用的后备方案要改协议，这些改动必须落在冻结之前 |
| D3 | **自用构建单独一套身份和数据目录**（`dev.cupper.app.local`、`cupper-local/`），开启 hardened runtime，只加 `disable-library-validation`，并且对 helper 也生效；关闭 `enableCookieEncryption`；T160 合并时附"自用前须知"（P-5、P-15） | 避免开发构建打断作者正在跑的会话、混用数据；关闭 hardened runtime 的话，同一用户的进程可以注入代码。桌面工程师原本建议关闭 hardened runtime，按安全工程师的意见裁定开启，桌面工程师已接受 |
| D4 | **复刻度贯穿全程**：<br>- T084 在 M1a 就建立 token 和三栏外框；<br>- M1b 开始前，作者补截参考图；<br>- T106 写视觉规格，M1b 的所有界面任务都依赖它；<br>- MAN-ui6 做两次；<br>- T148 做复刻度修正；<br>- 审阅用的截图在系统字体下截取 | 原计划只在 T152 检查一次复刻度，保证不了 |
| D5 | **T106 的参考图**（P-20）：子 agent 只读主仓库 `.private/references/` 里的参考图，产出文字规格；参考图不复制进 worktree，也不入库 | 参考图是作者本机的私有材料 |
| D6 | **兼容套件和真实运行的约束**：<br>- 兼容套件自我约束：显式设定权限模式，不选持久类选项，不放宽档位，只在临时仓库里运行；<br>- 真实录制入库前，先过一遍本机的敏感词清单，再由用户抽查；<br>- Codex 运行前，由用户自行备份配置，跑完后报告差异，由用户决定是否恢复（P-14） | 兼容套件以 test_harness 身份运行，绕过了档位规则；录制可能带有作者环境特有的信息 |
| D7 | **设计 v1.3 的 5.8.1**：<br>- `dev_key` 只接受拉起宿主的进程，按 `p_puniqueid` 判定；父进程退出后宿主进入孤立状态（P-19）；<br>- 各构建种类下，UI 和 CLI 分别怎样校验宿主；自用构建的 CLI 在编译期写入宿主的 cdhash；<br>- 落到 T005、T021、T030、T037、T045、T092 | 安全工程师指出，非发布构建的 CLI 认不出假宿主，假宿主可以劫持提权 |
| D8 | **Q35 不通过时的影响**，更正为两点：NFR-8 不成立；每次替换 App 后要重新确认 TCC 授权。CLI 在退化模式下照常可用，`install_cli` 不隐藏 | 见"事件记录"中的更正 |
| D9 | **其余条目**：<br>- P-3：编号统一成完整写法（设计 v1.2）；<br>- P-4：首个自用构建交付前，表结构只改 `0001`；<br>- P-6：设置页接口以附加方式加入；<br>- P-7：Q8 的后备做成条件任务；<br>- P-8 至 P-13：按计划处理；<br>- P-16 至 P-18、P-21：已由设计 v1.3 处理 | 见 `03-plan.md` 第 8 节 |

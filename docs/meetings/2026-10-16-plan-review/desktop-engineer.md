**修改后可以。** 没有阻断项。

## 对"待处理"条目的意见

### P-5 自用构建的种类

同意新增"自用构建"这一列，但不同意让它与开发构建共用身份、数据目录和认证。原因有两个：

1. **会中断作者正在跑的会话。** 自用 UI 拉起的宿主还在运行时，如果开发构建的 UI 连上来，`dev_key` 对不上，只能"重启宿主"（Q22），作者日常跑着的会话就被打断了。
2. **数据会互相污染。** `pnpm dev` 用的是还在修改中的 `0001`（P-4），共用 `cupper-dev/` 就会和作者的真实数据混在一起。

**建议的配置**：

| 项 | 取值 |
|---|---|
| 身份 | bundle id `<前缀>.app.local`（宿主 `.local.host`），显示名 "Cupper Local" |
| 数据 | 数据目录 `cupper-local/`，独立的 userData 和 worktree 根目录 |
| 深链接 | URL scheme `cupper-local://` |
| 认证 | `dev_key`（退化模式）；宿主开 `dev-auth`，不开 `test-harness` |
| 打包 | 打包方式和 fuses 同发布配置 |
| 签名 | ad-hoc 签名，关闭 hardened runtime（原因与 e2e 构建相同） |

**T160 的验收补两项**：

- 自用构建与开发构建可以同时运行，互不干扰；
- 宿主运行中手动替换 App（这是作者唯一的升级方式）时，旧宿主进入待升级状态，新 UI 显示等待，并能"重启宿主"（SP-4b 的 S1–S3 路径）。

Q35 通过后（T162），这一列再换成本机签名。

### P-6 设置页的"存储"和"安装命令行工具"

同意在 M1b 以附加方式加入。细节：

- **安装命令行工具**由主进程实现：`PrivilegedAction` 加 `install_cli`。
  - 让用户选目标目录，默认 `~/.local/bin`，不写需要管理员权限的 `/usr/local/bin`；在那里建一个指向 `Contents/Helpers/cupper` 的符号链接。
  - App 不在"应用程序"文件夹里，或者正在被转移运行（translocation）时，先提示用户移动 App，否则链接以后会失效。
  - K7 不通过时，自用构建里的 CLI 连不上宿主，这一项要隐藏或注明原因。
- **清除快照对象**：宿主方法的 scope 为 privileged，经原生确认框执行。
- **存储用量**：只读查询，scope 为 read。

### P-11 E2E-SEC-switches 的位置

同意放在 T161。这项检查只能在烧了 fuses、没有调试开关的构建上跑。另外，T161 应同时扫描自用构建的产物，因为作者每天用的是它。

- **P-2**：见 #6。
- **P-4**：同意。自用构建的数据目录单独之后，"T160 交付之后才加新的迁移脚本"这条分界就成立了。

## 对两个问题的回答

### 1. 粒度是否合适？有没有实际上没法并行的任务？

**粒度基本合适。**

- 主进程四段的边界清楚：骨架与加固；拉起宿主与 control 连接；windowBridge 与 preload；真实输入与特权操作。L 的理由也成立。
- ui-core 与主进程链确实可以并行。前提有两个：先解决 T070 的类型依赖（#1）；再用 HostPort 合同测试把两边的语义对齐（#11）。

**实际上没法并行、会互相改同一批文件的有这几组：**

| 任务 | 冲突点 | 见 |
|---|---|---|
| T081 / T082 / T083 | 新建会话页里的输入框、行列表里的卡片行、会话页布局 | #2 |
| T152 与 B1、B2 的界面任务 | 外框和 token 改动全部组件 | #3 |
| T141 / T140 / T142 / T145 | 都改输入框 | #4 |
| T144、T153 与 T152 | 新建会话页、标题栏、侧边栏 | #4 |
| M1b 各主进程任务 | 窗口、协议和菜单文件 | #4 |
| T091–T093 | e2e 辅助函数 | #13 |
| T077 / T078 | 同在 W8、同在 D.main 区 | #10 |

按上面的意见补依赖、在 T080 里先立好骨架和插槽之后，剩下的并行就是安全的。

### 2. 界面打磨的位置和拆法能不能保证复刻度？截图对比什么时候做、由谁做？

**按现在的拆法保证不了。** 原因有三个：

- 参考只有一张亮色主界面的截图；
- 只有 T152 一个检查点，之后的大批界面任务没人查；
- 最后用 T154 锁定截图基线，没有留出修正视觉的余地。

# 2026-11-23 体验类人工验收不再作为闸门

- 参与：用户、编排者
- 形式：对话

## 背景

M1b 剩下的任务里，T148（复刻度修正）等作者做 MAN-ui6-full，T108 等作者做 MAN-ime。此前作者做过的 MAN-keyboard 等人工检查，发现的都是体验上的小问题。

## 用户的话

> 按理说大部分都不需要我来参与实机验收，因为之前叫我验收的也只是一些体验小问题，这个如果后期我发现会叫你修复的，所以那种体验小问题就不用我参与验收了

## 决定

- **D1**：体验类的人工验收不再作为任何任务或里程碑的闸门。MAN-ui6-shell、MAN-ui6-full、MAN-ime 在 `tests/ids.toml` 改为 `na`；T179 不再"顺带检查交互细节"。作者以后用的时候发现体验问题，提出来，编排者立修复任务。
- **D2**：T148 不再等作者比对。执行者自己对照作者给的参考截图（`.private/references/`，私有，不提交、不引用内容）、本机 Codex 客户端的 App 包（F2，只读）、T106 的记录和交接事项，先出偏差清单和估算，编排者据此决定是否拆分，再修正。
- **D3**：T108 关闭：场景 5（浸泡）已完成，场景 6（MAN-ime）不做。输入法的自动覆盖仍是 UNIT-composer-ime（T086）。

## 仍需要作者的事

这些事不是体验验收，而是要用作者的账号、额度或数据：

- T105：本机签名身份（Q35）；
- T113：真实 Codex 的兼容矩阵（消耗额度）；

用户在同一天回答了上面留下的两件事。

- **D4**：MAN-S1 至 MAN-S4 改由子 agent 用作者本机已登录的 Claude Code 和 Codex 跑，作者不用动手，消耗的额度作者同意（新增 T273，排在 T113 之后，免得两个任务同时改 Codex 的配置）。T113 同样由子 agent 跑。安全约束照旧：
  - 只在临时仓库里运行；

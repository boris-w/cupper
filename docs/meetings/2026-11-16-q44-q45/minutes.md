# Q44 默认权限与 Q45 启动恢复

- 日期：2026-11-16
- 参与：用户、编排者
- 形式：会话中的提问（选项）

## 背景

- **Q44**：设置页"通用"里的"默认权限"（5.7.4）没有可接的东西。宿主没有新会话默认权限的设置键，新会话沿用 CLI 自己的配置；Claude 和 Codex 的权限模式不同，只在会话的能力里才有。要定：做不做、按不按 agent 分、默认是完全访问时每次新建会话是否还要确认。
- **Q45**：T103 发现 App 启动后总停在新建会话页、不恢复当前会话，而 5.9.6 的冷启动定义里有"当前会话已渲染"。要定：启动时恢复与否。

## 决定

- **D1（Q44）**：做。按 agent 各一个默认权限；默认设成完全访问时，每次新建会话仍经原生确认。
- **D2（Q44，编排者据 D1 定实现）**：
  - 宿主设置键 `sessions.default_permission.<agent>`，取值是该 agent 能力里的一个权限模式 id，没设时沿用 CLI 自己的配置；修改需要 `write`（只决定新建会话页的预选，不直接放宽任何会话）。
  - 新建会话页按它预选权限模式，经 `session/create.config.permission_mode` 发出；宿主照 5.8.2 的档位规则处理，所以完全访问每次都要原生确认，CLI 建的会话也不会因这个设置绕过确认。宿主不在 `session/create` 里自己套用默认值。
  - 设置页的选项来自 `agents/capabilities` 的缓存；存下的模式在能力里已不存在时，按"沿用 CLI 配置"处理，设置页提示。
  - 由 T144（新建会话页）一并实现设置页的这一行。
- **D3（Q45）**：跟 Codex 一样。用户实测：Codex 退出重开后停在新对话页，项目是上次那个对话的项目。所以 cupper 启动后停在新建会话页、预选上次所在会话的项目，不恢复会话；上次的项目已不存在时退回列表里的第一个项目（编排者据 T144 的问题定，与现在的做法一致）。5.9.6 的冷启动定义改为"新建会话页的输入框可用"。由 T144 实现预选。

## 落实

- 设计 5.2.11 设置表加 `sessions.default_permission.<agent>`；5.7.4 设置页"默认权限"一行写明预选与确认；5.7.4 新建会话页补启动时的项目预选；5.9.6 改冷启动定义；5.13 的 Q44、Q45 关闭。
- 计划 T144 一行补上默认权限和启动时的项目预选。

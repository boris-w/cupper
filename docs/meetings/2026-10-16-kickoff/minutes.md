## 讨论要点

### 1. 开发流程

用户提出：

> 这是一个新项目，我们要按照一个项目开发的流程来，从 PRD 开始。

编排者提出六阶段流程：PRD → 技术设计 → 任务拆分 → 迭代开发 → 验收发布 → 复盘。每个阶段产出一份 Markdown 文档，阶段结束时由用户确认后再进入下一阶段。PRD 只写"做什么、为什么"，技术选型放到技术设计阶段。文档详略随项目规模调整，个人项目的 PRD 一到两页即可。

### 2. 协作方式

用户提出：

> 你负责把控所有流程，代码开发和一些细节你要派遣子 agent，用 git + worktree 来协作，通过 commit 留痕。

编排者据此确定：编排者负责流程、文档和 review；子 agent 每次领一个任务，在独立 worktree 的独立分支上工作；代码一律经 review 后用 `--no-ff` 合入 `main`；阶段闸门通过后打 tag。

### 3. 留痕范围

用户提出：

> 所有工作也要留痕，包括可以和子 agent 探讨，开会同步等等，留下会议记录和工作物料。

编排者据此建立留痕体系：会议记录（`docs/meetings/`）、任务卷宗（`docs/tasks/`，包含 brief、notes、report、review 和物料）、ADR（`docs/decisions/`）以及各类模板（`docs/templates/`）。需要多视角判断的问题，召集多个不同角色的子 agent 开讨论会，各方原始发言作为物料保存。

## 决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | 采用六阶段、带闸门的开发流程，从 PRD 开始 | 用户要求按正规流程推进；闸门保证每一步方向经过用户确认 |
| D2 | 编排者 + 子 agent 分工，每个任务一个分支一个 worktree，`--no-ff` 合并，闸门打 tag | 并行开发互不干扰；历史中每个任务边界清晰 |
| D3 | 全程留痕：会议、讨论、派发、汇报、review、物料都写成文档提交 | 用户要求所有工作可追溯 |
| D4 | 记录统一用本地 Markdown 文件随仓库提交 | 与代码同版本管理，可以用 git 追溯 |

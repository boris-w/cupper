## 逐项意见

1. **"空闲"的定义**（六条同时满足）：没有运行中的回合、待处理的交互、会出队的排队消息（暂停中的不算）、核心计时器、在途的重扫或连接、等信任检查的 `send` 回复。订阅者不算活动。与任务书一致，而且比任务书写得更完整（核心计时器、在途重扫、等检查的 `send`）。
2. **退出的顺序**：actor 先关闭 agent 会话、放下全部部件（含流写者）、把收件箱交回；管理器再 `forget`（邮箱匹配才撤出）、关闭收件箱、把已在收件箱里的调用经按需载入重新投递。先放写者避免新载入遇到 `WriterTaken`，先撤邮箱避免新调用落进正在退出的收件箱，退出那一刻已投递的调用照常处理。顺序正确。
3. **退出时关闭 agent 会话**：不留一个没人接收事件的会话；下一个 actor 照 T089 的规则 resume。
4. **订阅时载入**：网关处理会话流的 `stream/subscribe` 时调 `SessionPort::wake`，会话不在内存就按需载入，载入失败不影响订阅。解决了 T091 发现的"重启后窗口显示过时状态"。对不存在的会话也会起一次载入，代价是一次读，可以接受。
5. **静止屏障**：等定时器时处在 `Participant::idle`，到时被唤醒即算忙；测试经 `SessionManager::settled`（只在测试里编译）确认在途工作结束再推进时钟，用例是确定的。
6. **宿主层的空闲退出（T059）是另一套计时**，没有混用。

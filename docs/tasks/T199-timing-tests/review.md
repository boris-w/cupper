## 逐项意见

1. **第 1 处**：根因是合并窗口的起点跟着第一条事件走，第一段输出来得晚就会分进两批。改用手动时钟、回合结束后推进时钟来结束窗口，用例不再依赖真实时间。只放宽等待修不好这个问题，认可。
2. **第 2 处**：用 runner 上的 550 次连跑和 `sample` 采样，定位到主线程停在 Electron 默认的同步错误框里，起因是主进程没有处理一处异常。这是产品问题，照约定停下汇报、只留诊断、转交 T200。做法得当。
3. **第 3 处**：根因是假 agent 先把 20 万条全部排进队列才写出第一条。改为每次 2,000 条交替写出；kill 的时机和恢复后的检查都没变，用例要验的东西没有削弱。
4. **第 4 处**：预跑收进 `common::start`，每个路径只跑一次，比 T196 的两处显式调用干净。
5. **第 5 处**：`fake_agent_host_from` 返回 `Running`，有桩程序做修前修后对照。
6. **`test-repeat.yml`**：输入经环境变量传入，`args` 用 `read -r -a` 拆分，没有 `eval`；单次限时，过滤条件没匹配上也算失败，防假通过。原版有 `bash -e` 的错，已由 PR #10 修好。

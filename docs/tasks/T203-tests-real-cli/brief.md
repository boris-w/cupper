# T203 宿主测试找到本机真实的 CLI

- 派发日期：2026-10-28
- 执行者：子 agent（Rust 工程师）
- 分支：`test/T203-tests-real-cli`
- 依赖：T201（已合并或即将合并，见"工作方式"）。T099 依赖本任务

## 背景

T201 发现：IT-runtime-startup 等没有配置 `test_config.agents` 的宿主用例，走的是生产路径的 CLI 发现（设计 5.6.6），而宿主沿用测试进程真实的 `HOME`。本机在常见位置（`/opt/homebrew/bin/claude`、`~/.local/bin/claude` 等）装了 Claude 时，宿主启动时会对它执行一次 `claude --version`。

这不耗额度，但违反了"所有自动化测试都不运行真实 CLI"（设计 5.9 的原则）。CI 的 runner 上没有装 Claude，所以只在开发者的机器上出现，也就一直没暴露。

## 范围

**做**：
1. **找出全部会走到生产 CLI 发现的测试**：宿主的集成测试、进程级用例、e2e（经 UI 拉起的宿主）、CLI 的测试。列成清单写进 `notes.md`，每一处写明它是怎么拉起宿主的。
2. **让测试只看得到测试自己放的程序**：
   - 共用的测试夹具给宿主一个只在测试目录里的 `HOME`，以及登录 shell 的环境（`test_config.login_env`，5.9.9），让常见位置、登录 shell 的 PATH 都指向测试目录；
   - 需要真的找到一个 CLI 的用例，照 T201 的做法，用设置的 `cli_path` 或 `test_config.agents` 指向假 agent；
   - 不改生产路径的发现逻辑。只有测试注入点不够用时才动宿主代码，先汇报。
3. **新增 IT-host-tests-no-real-cli**：断言测试里宿主发现到的 CLI（以及对它执行过的 `--version`）都在测试目录之下。做一次修前对照：本机有 Claude 时，修复前这个断言会失败；本机没有时，用一个放在假"常见位置"里的探针程序来证明。
4. 已经登记的用例照常通过，期望值有变的逐条说明。

**不做**：改 CLI 发现的规则（T054）；兼容套件（真实 CLI 本来就是它的目的）。

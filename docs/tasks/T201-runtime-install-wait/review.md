## 逐项意见

1. **等的是界面看到的状态**：启动前等索引里 Claude 适配器的 `runtime` 变成 `ready` 或 `failed`，不新增协议成员，符合契约冻结的规则。
2. **等待不占 actor，并且可以放弃**：启动本来就在另开的 task 里。给它加一个 oneshot，宿主退出时等待随即结束，不会被下载拖住最长 60 s。只在等安装这一段可以放弃，进程拉起之后不放弃，免得留下孤儿进程。考虑得周到。
3. **按安装器的计划启动**（refactor 提交）：原来启动时固定用内嵌清单，测试包里的安装器却按 `test_config` 的清单安装，两者对不上，所以以前写不出这个用例。生产环境里两者是同一份清单，行为不变。
4. **IT-runtime-first-prompt-waits**：用注册表闸门控制时序，靠事件保证顺序，不用 sleep。两段都覆盖到：装好后回合完成；装失败时以 `runtime_failed` 结束、`failure` 为 `hash_mismatch`。CLI 用设置指定假 agent，避开了本机真实的 Claude。

# D03 带界面的 PRD（HTML）

- 派发日期：2026-10-19
- 执行者：子 agent（产品设计师）
- 分支：`docs/D03-prd-ui-html`
- 依赖：PRD v1.2、设计 v1.3、计划 v1.0（`gate/plan`）

## 背景

开发开始之前，用户想先看一份"带界面的 PRD"，对做出来的东西心里有底。现有的 PRD（`docs/01-prd.md`）全是文字，界面的样子分散在截图笔记、R01 报告和设计 5.7 里。

## 目标

做一个单文件 HTML：`docs/01-prd-ui.html`。用户用浏览器打开后，能看到三样东西：
- cupper 做完 M1（M1a、M1b）之后，每个主要界面长什么样；
- 每个界面元素对应 PRD 的哪条需求、在哪个里程碑交付；
- M2 到 M4 大致会增加什么，尤其是 M3 的 iOS 端。

## 形式要求（必须遵守）

- **纯 HTML**：简单的标签，最少的 CSS（写在 `<style>` 里）。可以用 mermaid 画流程图：从 cdnjs 或 jsdelivr 加载锁定的版本，例如 `mermaid@11.4.1`。除 mermaid 外，不引用任何外部资源，不用 JS 框架。不做花哨的视觉设计。
- **界面示意图**用 HTML 加 CSS 的方框画成线框图，风格接近 Codex 桌面版：中性的颜色、三栏布局、细边框。不使用 OpenAI 或 Codex 的任何品牌素材、图标和 logo。
- 每个示意图都用编号标注（①②③…），图下用表格写明：编号、元素、说明、PRD 需求编号、里程碑（M1a、M1b、M2、M3、M4）。
- **内容以文档为准，不发明功能。** 示意图里出现的每个元素，都要能在 PRD 或设计里找到依据。还没定的地方（例如待定问题）照实写"待定"，并写明问题编号。
- 中文。文风：先给结论，表格和列表优先。
- **不使用** claude.ai 的 Artifact 工具，也不调用任何 artifact 相关的 skill。只产出这个本地文件。

## 内容（建议的结构，可以调整）

1. **开头**：
   - 产品一句话定位；
   - 用户和场景；
   - 里程碑时间线（M1a、M1b、M2、M3、M4，以及推迟的"发布"），每个写一两句交付什么；
   - "这份页面怎么读"。
2. **主界面全景**（M1b 完成后）：三栏示意图，带编号标注。
   - 侧边栏：项目、会话、状态、未读、"未信任"标记、弱认证标记；
   - 会话区；
   - 右侧工作区（审查面板）。
3. **逐个界面**，每个界面一张示意图、一段说明、一张需求对照表：
   - 新建会话：选 agent、本地或 worktree、分支、模型、推理强度、权限模式。
   - 消息流：
     - 用户消息、思考（可折叠）；
     - 工具活动的单行摘要与分组、命令输出的展开；
     - 回合折叠（运行中展开；结束后收起过程，只留最终回答和"用时"）；
     - 计划和待办（注明 Claude 与 Codex 的差异，见 PRD 第 10 节 Q12）；
     - 错误与恢复指引、提示、晚到的工具输出（"取消后仍在运行"）。
   - 审批卡片：Enter 批准、Esc 拒绝；选项以 agent 的原文为准；标注持久选项；各种状态（待处理、已在 cupper-cli 处理、已在别处处理、已失效）。
   - 提问卡片、计划确认卡片。
   - 输入框：多行、`@` 引用文件、图片、斜杠命令、排队条、Steer、中断。
   - 审查面板：
     - 未暂存、最近一回合，以及最小的"已暂存"范围（Q13）；
     - 文件列表、diff；按全部、文件、hunk 暂存，取消暂存，还原；
     - 行内评论一键发给 agent；
     - 提交、推送，以及"将运行仓库 hooks"的提示；
     - 仓库配置变化的提示。
   - 原生确认框，画成 macOS 系统对话框的样子：
     - 添加项目时的信任确认（列出 hooks、MCP 等）；
     - 切换到完全访问；
     - "总是允许"类选项；
     - CLI 提权申请（区分"宿主核实的信息"和"申请方自述"）。
   - 设置页：
     - agent 状态：CLI 路径、版本、已验证范围、登录状态、运行时、资源占用、重启；
     - 通用、通知、外观、存储、安装命令行工具；
     - "本地鉴权较弱"的说明（自用构建）。
   - 系统通知的示意。
   - cupper-cli：终端截图式的示意，用 `<pre>`，展示 M1a 的第二客户端。
   - **M1a 最简界面和 M1b 完整界面的对比**：M1a 有哪些、没有哪些（设计 5.12.2、5.12.3）。
   - **M3 的 iOS 端**：手机尺寸的示意，包括扫码配对、会话列表、会话详情和审批。注明手机端的限制：不能选"总是允许"，不能切到更宽松的档位，不能切到完全访问（SEC-9）。
4. **关键场景**：S1–S7，每个画一张简短的 mermaid 流程图或时序图，或者写成分步列表，注明里程碑。
5. **需求总表**：按模块列出（AG、PS、CP、MS、AP、GT、UI、MB、SEC、NFR），包括编号、一句话、优先级、里程碑、出现在哪个界面。P1、P2 可以简写。
6. **边界**：
   - 不做什么，例如集成终端在 M2、不上 App Store；
   - 自用阶段的安全须知要点：退化认证的含义、开启 agent 自带的沙箱、在 cupper 里提交会运行仓库的 hooks；
   - 与 Codex 的差异：同时支持 Claude Code 和 Codex、手机接管、宿主架构。

## 验收标准

- [ ] `docs/01-prd-ui.html` 是单个文件，用浏览器直接打开就能看。除了锁定版本的 mermaid，不依赖任何外部资源。

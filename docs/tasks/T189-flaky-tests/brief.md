- 依赖：无。T099 依赖本任务

## 背景

M1a 的退出验收（T099）要求在同一个提交上**连续 20 次全绿**，不允许重试、跳过或隔离用例，中途失败一次就查明根因、计数清零。所以偶发失败必须在那之前清掉。T069 跑带记录的 CI 时，碰上了两处与它无关的偶发失败，当时本机负载约 9，重跑都通过了：

1. **E2E-SEC-real-input**（T092 的用例，在 `test-e2e-focus` 段）：等请求面板的"手动"提示时超时。
2. **`unit_fake_scripts_faults_per_segment`**（`cupper-fake-agent` 的单元测试）：报 "the agent did not exit"，`exit_on_start` 的假 agent 在 10 s 内没有退出。这条用例单跑 20 次都通过。

## 范围

**做**：
1. **先复现**：在高负载下循环运行，记下失败率。负载可以用别的 worktree 的整套测试，或自己起几份整套测试在后台循环，照 T093 修复 1 的做法。
2. **查明根因**：
   - 是用例的等待在负载下偏紧，还是产品的行为在负载下真的变了（例如面板的状态切换、假 agent 的退出路径）；
   - 原因在产品里、并且在计划 1.2 的上限内（单处不超过 100 行、不改接口）的，就地修，单独提交；
   - 超出的停下汇报。
3. **修复用例**：
   - 只放宽等待时，要说明为什么放宽是对的，而不是在掩盖问题；
   - 不要用"失败就重试"。
4. **同类排查**：两条用例所在的文件里，有同样写法的用例一并检查。

**不做**：其他偶发失败。发现了记下来，在汇报里提出。

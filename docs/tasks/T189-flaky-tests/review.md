2. **E2E-SEC-real-input**："请再按一次"是规则 7 规定的提示，产品照设计在做，问题在用例依赖启动时碰巧拿到的焦点。改用 `focusWindow` 抢焦点、等到确实拿到再等 1.1 s，是对的。
3. **信任复查的竞态是真实的产品问题**：旧结果会把刚打开的闸门再关上，还多发一次通知，首个回合因此停在准备阶段。T064 那次挂了 28 分钟就是这个原因。修法给复查编号，旧结果改用最新那次的结论，不翻转闸门、不重复通知，Check 和 Attach 仍照常答复。产品逻辑约 30 行，不改接口，在计划 1.2 的上限内。
4. **同类排查**：`quiet` 在 agent 退出后改为直接失败，不会再假通过；`call` 加了 30 s 上限并报出在等哪个方法。这条用例走到的等待现在都有上限。

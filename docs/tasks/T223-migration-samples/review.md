## 逐项意见

1. **两道防线**：
   - 已发布脚本的 sha-256 固定在 `RELEASED` 里，原地改脚本或者加了脚本没登记，CI 都失败；
   - 样例里原样保存的表结构，必须等于当前脚本在空库上建出来的结构，所以连哈希一起改也绕不过去，除非同时改冻结的样例文件，那在 diff 里很显眼。
   变异检查验证了这两种情形。
2. **"已发布"的界定对**：自用构建直接从 `main` 出，所以 `main` 上的脚本都算已发布。锁做成普通的 cargo 用例，不依赖 CI 上取不到的 git 历史。
3. **样例由宿主生成**：剧本覆盖工具调用、blob、权限请求、排队、中断和安全设置，每张表都有数据，也不会覆盖已有的样例。

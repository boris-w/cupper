# T217 点击请求面板后键盘能操作面板

- 派发日期：2026-11-02
- 执行者：子 agent（TypeScript / React 工程师）
- 分支：`fix/T217-panel-click-focus`
- 依赖：无（T099 的 MAN-keyboard 发现）。T099 依赖本任务

## 背景

2026-11-02 用户在 e2e 构建上用实体键盘做 MAN-keyboard（T099），发现：

1. **点击面板卡片不会把键盘焦点移进面板。**
   - 面板没有自动接管键盘时（RP-3：请求到达时焦点不在输入框、输入框不空、或 2 秒内打过字），会提示"按 Tab 或点击以处理请求"。
   - 点卡片空白处时，`RequestPanel` 的 `onMouseDownCapture` 只把状态设为 active，DOM 焦点没有移进面板，按键落到 body 上，Enter、数字、Esc 都没反应。
   - 点选项行会直接提交这个选项。
   - 结果是"点击"这条路实际不起作用，只有 Tab 有效。有一次要按两下 Tab：第一下落在了面板外面的元素上。
   - 用户的原话："按理说我直接点击到这个对话或者这个卡片，应该自动聚焦吧"。
2. **有两次，用户先点了输入框，面板却没有自动接管键盘**（3b 的两次；1、2、3a 等几项是自动接管的）。原因没查清。

## 范围

**做**：
1. 点击面板卡片的非交互区域（标题、说明、内容区的空白处），把键盘焦点移进面板（选项列表），之后 Enter、数字键、Esc 照常工作。
   - 点选项行、按钮的现有行为不变。
   - RP-2（就绪前的点击不算）和 RP-8 的规则不变：就绪前的点击既不激活，也不移焦点。
2. Tab 从输入框区域一下就能进到面板，不先落到面板外的元素上。如果做不到，说明原因。
3. 查第 2 条：自动接管什么时候会失败（比如窗口不在前台时输入框的 `focused` 状态、上一个面板关掉后输入框重新挂载的时机）。查清后能修就修；修不了就写清楚条件，交编排者定。
4. 用例：
   - ui-core 单元测试覆盖"点空白处后按键作用于面板"、"就绪前点击不移焦点"；
   - 第 2 条查清的话也要有用例。
   - 挂在已有编号下（UNIT-request-panel 一类）；需要新编号先告诉 `main`。
5. e2e 能覆盖的部分（点击后用 Playwright 按键）可以加，挂在已有的面板用例下。

**不做**：改真实输入的核对、冷却规则和 RP-3 的判定条件本身（除非第 2 条查出是判定条件的缺陷，先报编排者）。

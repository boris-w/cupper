## 逐项意见

1. **改的是"等什么"，不是"等多久"**：正向断言都改为等条件成立（`until`，即 `vi.waitFor`，上限 5 s，超时时报出在等什么）。
2. **"什么都没到"用探针做屏障**：在同一条连接上再发一个 `host/status`，等它的回包回来。消息按顺序处理，探针回来了，它前面的就都处理完了。不靠睡眠，做法可靠。
3. **取消订阅的用例**补上了"先等第一条"，修前那条 `[2, 0]` 的失败正出在这里。
4. **保留的两处 50 ms 停顿**都在"端口关闭后什么都不发"的负向断言里：没有回包可等，也发不了探针；负载高时只会漏掉错误，不会误报失败。认可。
5. **同类排查**：e2e 里等输入守卫的 1 s、2 s，等的是产品规则规定的时长，保留有理。

## 记下的点

- 以后写测试，"等固定时长再断言"一律改为等事件；断言"什么都没发生"的，优先用同一通道上的探针做屏障。

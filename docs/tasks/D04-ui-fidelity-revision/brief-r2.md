## 背景

安全工程师对请求面板的规则给出"附条件可以"：可以接受数字键直接提交，但"必须补的"一节列了 6 条，需要写进设计和计划。

## 要落实的（详见安全确认原文）

1. **面板焦点**（设计 5.7.8 RP-3 等，任务 T083；T092 的 E2E-SEC-panel-arming 补场景）：
   - 输入框里有未发送的草稿时，面板不自动获得焦点；
   - 面板获得焦点后，一收到打字键，就撤销它的键盘可操作状态，回到"按 Tab 或点击以处理请求"；
   - 提示"再按一次 Enter"只用在窗口刚被激活后的冷却期；
   - 面板获得焦点后，第一下 ⌘Enter 不提交。
2. **导航键**（第 2、3 条，任务 T077 的 inputGuard，UNIT-input-guard）：导航键不会触发第 3 条，但会清掉还没用掉的输入。
3. **编号**（RP-6，任务 T083 的渲染与 T031 的宿主核对，UNIT-policy-matrix 和 E2E 补用例）：
   - 显示的编号一律等于选项在 `options` 里从 1 起的序号，特权选项和效果未知的选项也占编号；
   - 按效果未知选项的编号不起作用；按特权选项的编号走 `requestPrivileged`；
   - 不允许重新排序。
4. **还原确认**（RP-11，任务 T130、T131；E2E 在 T093）：
   - 由审查文档消息触发的还原确认，不自动获得焦点，同一时间只显示一个；
   - 由主文档按钮点击触发时，焦点可以按 Codex 放在"确认"上。
5. **拒绝并附一条消息**（任务 T083；插话路径在 T140；IT 或 E2E 在 T093）：
   - 先等拒绝成功再发送；
   - 收到 `already_resolved` 或 `expired` 时，文字留在输入框里，并提示"已在别处处理"；
   - 遵守"默认排队"的设置和 agent 的插话能力；
   - 消息流里标明这条消息附属于哪一次拒绝。
6. **其他**：
   - T150 加单元测试，断言系统通知没有任何操作按钮；
   - Q41 写明"数字键选中即提交"在 Codex 里是否如此尚未核实，交 T106 核对；设计里"与 Codex 相同"一句改为"未核实"；
   - MAN-keyboard 包含数字键，保留。

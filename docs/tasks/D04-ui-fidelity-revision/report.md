## 一、安全落点：交安全工程师确认（设计 5.7.8，待定问题 Q41）

审批和提问不再是消息流里的卡片，改为替换输入框位置的请求面板。真实输入规则的改动如下。

**主进程的规则**

- 第 2 条：
  - 按键白名单增加数字键 1–9。
  - ↑ ↓ ← → 定为导航键，既不算真实输入，也不算打字键。不这样定，"按 ↓ 再按 Enter"会被第 3 条拦下。
- 第 3 条：刚打过字的 1 秒内，数字键也不算真实输入。
- 第 4、5 条：
  - 新增证据 `input.key: digit` 加 `digit`；
  - 宿主核对：对权限请求和计划确认，`digit` 必须等于所选选项的序号（宿主 5.2.5，任务 T031）。
- 第 7 条："卡片满 500 ms"改为面板的待命期。

**请求面板的规则（新增 RP-1 至 RP-11）**

- RP-1 待命期：面板出现、或下一个请求接替时，有 500 ms 待命期。期间的按键和点击都吞掉，有按键就重新计时。
- RP-2 点击：只认面板可以操作之后才按下的点击。
- RP-3 焦点：
  - 焦点原在输入框、并且最近 2 秒没打字时，焦点移到面板上；
  - 刚打过字时，面板不自动获得焦点，要按 Tab 或点击才响应；
  - 焦点原在别处时，面板不抢焦点。
- RP-4 初始选中：跳过特权选项和效果未知的选项。
- RP-5 数字键：选中即提交，与 Codex 相同。
- RP-6、RP-7：效果未知的选项只能点击；特权选项一律走原生确认框。
- RP-8：连续两个请求时，后一个重新待命。
- RP-9：面板上方有弹出菜单时不响应按键。
- RP-11：主文档里的还原确认控件也有待命期；默认焦点按 Codex 放在"确认"上。

**有意与 Codex 不同的两处**

- 系统通知上不放"批准"按钮。理由：按钮点击没有真实输入证据，也不经过原生确认，通知里还看不到完整命令。
- 还原确认框不提供"不再询问"。理由：被还原的改动无法恢复；而且审查文档发来的还原必须经过主文档里的这个控件。

**退回方案**：安全工程师不接受"数字键直接提交"时，改为"数字键只选中，Enter 提交"。

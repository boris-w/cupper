## 进程级用例的执行者核对（测试 #3）

方法：

1. 列出每个进程级用例（真实宿主进程、真实适配器进程、Electron、真实 git 仓库上跑的 IT、E2E、PERF、GOLD-B），写明它所属的任务，以及它运行时需要的执行者，即实现了被测路径的任务。例如 IT-cli-commands 需要宿主的启动顺序（T037）、会话（T043、T044）、驱动（T055）和提权（T038）。
2. 对每个用例，检查两件事：
   - 编号确实出现在所属任务的"验收"一栏；
   - 每个执行者都在所属任务的前置闭包里，即沿依赖可达，或者就是它自己。
3. 反过来，扫描全部"验收"一栏里的 IT、E2E、PERF、GOLD-B 编号。每个都要么在第 1 步的清单里，要么明确归为进程内或 crate 内的用例，例如 IT-orch-lifecycle、IT-git-hunk。没归类的算错误。
4. 另查两项：
   - 每个里程碑的退出任务（T099、T179）的前置闭包，包含本里程碑的全部非条件任务；
   - 同一个编号没有被两个任务同时认领。互为替代的条件任务（T131 与 T139、T150 与 T158）、按 Electron 大版本重复的 MAN-keyboard、T079 对 PERF-bridge-gate 的复测除外。

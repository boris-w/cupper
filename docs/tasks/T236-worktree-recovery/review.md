## 逐项意见

1. **在 `add` 里看已有状态**，不按崩溃点分支：新建和恢复走同一段代码，只要状态是 git 能表达的都能接上。代价只是新建时多一次只读调用，值得。
2. **两个故障点放在确定的位置**，重启后分别走"`-b` 新建"和"已登记、补 lock"两条路径。断言包括：一致性检查、`command_id` 幂等、`workspace.ready` 恰好一条、没有重复和孤儿。
3. **我要求补的那种情形处理得对**：已登记但目录已删时报 `not_found`，不 `prune`（会清掉用户自己的其他记录），不 `--force`（会越过用户的锁），git 里的记录留给用户处理。
4. **三处变异检查**都能让对应用例失败。

## 逐项意见

1. **纠正了任务书的推测**：restart 和 prompt 走同一个信道，到达顺序有保证；没有保证的是 prompt 到达时停止做完了没有。证据是本机插入真实等待后能确定性复现。
2. **核对构件时多找出一个原因**：取消的定时器要等这一步结束才从 `ManualClock` 撤掉，用例一听到事件就推进时钟，可能推到已取消的截止时间。只在测试时钟上出现，产品不受影响。
3. **两条路径都有确定性的用例**："停止期间到达"用 `--fault linger` 让停止只能靠推进时钟完成；"实例结束之后到达"先等 `AdapterExited` 再发。`Fixture::settled()` 用一次 `status` 往返确认运行时那一步已经做完，做法干净。
4. **产品行为查清了**：两种先后都不丢消息、不挂回合，不改产品。

# T126 评审

- 评审人：编排者
- 日期：2026-11-03
- 结论：**通过，合并**（PR #52）

## 核对

- **规模**：+631 −14。越过停止线 600 时执行者停下报告；我没有同意为了行数压缩应用清单和测试，放宽到 650，硬停止线 750 不变。
- **CI**：PR #52 https://github.com/boris-w/cupper/pull/52 ，cf2b7c3 上 8 个检查全绿（run 41612677429），其中 license 作业用最新的 advisory 库检查了新依赖。
- **个人信息**：改动的文件过了敏感词清单，干净。测试没有打开任何真实应用，替身 `open` 只记录参数。

## 逐项意见

1. **许可证裁定**：设计指定的 nucleo-matcher 是 MPL-2.0，不在 ADR-11 的白名单里。我没有开这个口子：白名单只收宽松许可证，MPL 会给发行带来源码获取方式的义务。改用 MIT 的 fuzzy-matcher 0.3.7，`ignore` 是 Unlicense OR MIT。`cargo deny` 全部通过。
2. **缓存的失效时点对**：会话 actor 在提交 `turn.completed` 那一批之前丢掉自己工作区的列表，客户端看到回合结束时拿到的已经是新列表。
3. **提示内容映射**：不支持的块让 prompt 失败，不悄悄丢掉，原因由 T226 的 error 条目显示；`file_ref` 不能越出工作区。
4. **`workspace/open`**：只接受内置清单里的应用名（设置更新时和打开前都查），`open -a` 经 `cupper-sys::spawn`，参数不经 shell，环境为空。

## 记下的点

- **设计**（本次合并时改）：5.2.11 的匹配器改为 fuzzy-matcher（T126 裁定），写明缓存在回合结束时失效、快照档失败时改走遍历、内置应用清单；时长表登记 `file_list_ttl`（5 s）、`app_open`（30 s）。
- **交接事项**（已写入 handoff-notes）：
  - T151、T153：默认编辑器 TextEdit 打不开文件夹，要改默认值或引导用户选择；
  - COMPAT 或真机验证：`resource_link` 的 `file://` uri 没有百分号编码；
  - 输入框或会话的后续任务：图片和越界引用可以在 `session/send` 时提前校验。

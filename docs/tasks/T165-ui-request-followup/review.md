## 逐项意见

1. **RP-12 的顺序**：先 `interaction/respond`，收到成功才发 `session/send`（`mode: queue`、`reply_to`）。`already_resolved`、`expired` 归为新的 `elsewhere`，不发跟进、文字放回输入框、提示"已在别处处理"。普通回答遇到同样情况也给这条提示，比原来的"失败"准确。
2. **刚打完字的 Enter**：渲染进程先判断，1 秒内只提示"点击提交"、不发请求。这不削弱主进程的真实输入检查：真正发出的请求仍要过 inputGuard；渲染进程这一步只是少发一次注定被拒的请求，并选对提示。输入法组字中的 Enter 记为打字。
3. **自由输入行只在有不持久的拒绝选项时出现**，编号为"选项数 + 1"，数字键只聚焦、不提交。
4. **请求记录行**：记录文字由纯函数 `record()` 决定，行组件只依赖 `row`，守住 T082 的约定。"等待处理"也算一种状态，流里不留空行。
5. **"1 / n"**：只在多于一个待处理请求时显示，文案走 i18n。

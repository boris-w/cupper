- 分支：`test/T066-claude-compat-real`

## 背景

兼容套件的框架（T064）、真实模式与自我约束（T187）、报告工具（T188）、21 个剧本（T192）、评审工具（T194）都已合并，但还没有用真实 CLI 跑过。本任务第一次在作者机器上用真实的 Claude Code 跑全套，产出第一批 B 层录制和金样例、兼容报告，以及由报告生成的"已验证 CLI 范围"。

用户已许可本任务使用真实的 Claude CLI，会消耗额度（2026-10-28；计划第 6 节第 7 行）。用户今天在场，负责抽查要入库的录制和报告。

## 范围

**做**（计划 T066 一行和注；设计 5.9.3、5.9.5）：
1. **先演练再真跑**：先 `--real --dry-run` 核对计划，再从一个便宜的剧本开始真跑，确认链路通了再跑全套。可以用 `--only` 分批跑。
2. **全套真跑**：
   - 适配器保持锁定的 claude-agent-acp 0.91.0；
   - 思考流剧本（COMPAT-claude-thinking）用 sonnet 或 opus，其余用最便宜的模型（例如 haiku）；
   - 剧本包括 T003 加的三个：6 个会话并发（COMPAT-claude-six-sessions）、关闭时有命令正在运行（COMPAT-claude-close-running，K21），以及多次 resume 同一会话后的 `claude` 进程数（COMPAT-claude-resume-procs，Q43）。
3. **录制与金样例**：
   - 新增 GOLD-B-claude，至少覆盖普通回合、审批、取消三个剧本；
   - A/B 层金样例照 T065 的流程产出；
   - 录制和报告入库前先过本机敏感词清单（`--write` 会检查），再交用户抽查（见"用户参与"）。
4. **已验证 CLI 范围**：
   - 由 `cargo xtask compat-reports --write` 从入库的报告生成，不手填；
   - 适配器升级后基线怎么取由本任务定（T188 的交接），写进汇报。
5. **问题结论**：写下 Q8 复核、Q10、Q28、Q34（Claude 部分）的结论，以及 MAN-compat-claude 的证据。Q28、Q34 的结论还要写清它们对信任扫描范围、安全边界说明（5.8.7）的影响，由编排者改设计。
6. **0.93 候选**：
   - 只作为候选版本跑，不升级锁定版本；
   - 任何剧本、任何 prompt 都不发送 `/remote-control`（Q42：它会把会话交给 Claude 的网页版或手机 App）；
   - 候选版本的报告不计入已验证范围（适配器版本不等于锁定版本）；
   - 要是跑候选版本需要改产品代码或运行时清单，就不跑，在汇报里写明缺什么。
7. **交接事项**（`handoff-notes.md` 第一列含 T066 的行）逐条核对，结论写进汇报：
   - T054：常见安装位置、nvm 的取舍；
   - T053：`compaction_update`；
   - T063、T003：Q43 的进程数；
   - T064、T187、T192：真实模式第一次运行时要留意的各项；
   - T188：已验证范围；
   - T194：评审工具；
   - T196：`VERSION_PROBE` 的 5 s，实际量一次，需要时提出调整；
   - T004：适配器升级时重新评估静态扫描（只评估，写进汇报）。

**通过条件**（K12，计划 T066 的注）：
- 剧本结果允许"不确定"，但 GOLD-B-claude 至少覆盖普通回合、审批、取消；
- 每个剧本最多重试 3 次，整套最多重跑 2 次；
- 超过上限仍不行时，停下汇报，由用户决定 M1a 是否先退出、真实 B 层是否挪到 M1b 开头。

**不做**：
- 升级锁定的适配器版本；
- Codex 的兼容套件（T113）；
- 修产品代码里的缺陷：真跑发现的产品问题记下来，停下汇报，由编排者另开 fix 任务。

兼容套件框架本身的小问题（判定规则、等待上限、剧本步骤）可以在本任务里修，每处在汇报里说明理由。放宽任何检查前先汇报。

## 约束（安全要求，必须遵守；计划 1.10，安全 #4、#5）

- 兼容套件以 test_harness 身份运行，自我约束照 T187，不为通过而放宽。
- 只在套件自己建的临时目录里运行，不用作者的任何真实项目。剧本固定，不让模型联网取内容。
- 权限模式照剧本显式设定（Claude `default`），只选不持久的选项（`allow_once`、`reject_once`），不选任何"总是允许"类选项。
- **不修改任何用户配置**。
  - 用户配置只经套件做运行前后的哈希对比，报告里只写字段名和"是否变化"，不写内容。
  - 除此之外不读 `~/.claude`、`~/.claude.json` 的内容。
- Claude CLI 运行时自己写入的会话记录、项目目录，列成清单写进主仓库的 `.private/cleanup/T066-leftovers.md`（不入库），由编排者请用户确认后再清理。子 agent 不删除这些内容。
- 入库的录制、报告、notes 里不出现个人信息：用户名、本机路径、会话 ID、网关域名、MCP 服务器和 hooks 的名称等。
- 负载：一次只跑一份套件，不并行跑多份，也不循环重跑（守则第 10 条）。
- ADR-11：Claude Code 的二进制和 Anthropic 的 SDK 不进入仓库，录制里也不夹带。

## 用户参与

- **敏感词清单**：由用户在主仓库建 `.private/sensitive-words.txt`。
  - 子 agent 不代写；
  - 第一次 `--write` 之前，用 SendMessage 问 `main` 清单是否已建好；
  - 清单不存在时 `--write` 会报错，不要绕过。
- **抽查**：录制和报告准备入库时，先在本机提交，再用 SendMessage 发给 `main`，列出：
  - 待抽查的文件；
  - 每个文件的大小；
  - 敏感词扫描的结果。

  编排者转给用户抽查，用户确认后再请求推送。
- **额度**：真跑开始前，用 SendMessage 告诉 `main` 预计的回合数和模型，编排者转告用户。

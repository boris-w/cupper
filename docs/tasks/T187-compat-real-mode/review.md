## 逐项意见

1. **进入真实模式要显式写 `--real`**。参数组合的约束都有用例：`--model` 只配 `--real`，`--words` 只配 `--write`，`--dry-run` 不配 `--write`。真实模式加 `--write` 时拒绝 `--only`（T188 的要求）。
2. **自我约束分三段**：
   - 运行前做静态检查：模式在允许清单里，选项种类只允许 `allow_once`、`reject_once`；
   - 运行中按宿主给的风险检查：所选模式必须是 `normal`，选项不能要求 privileged、不能是持久的；
   - 剧本跑完后检查进程：适配器以下的进程不持有宿主的管道和套接字，宿主退出后 5 秒内都要退出。
   - `loosens` 只放宽模式和选项，不放宽选项种类，也不放宽"只在本用户临时目录"。
   - 允许清单里加 Claude 的 `plan`，认可：它比 `default` 更严，运行中还会按风险再核对一次。
3. **配置对比照 T003**：settings 两个文件和 `config.toml` 按整文件算；`~/.claude.json` 只看和权限有关、会拉起程序的字段。报告里只写名字和是否变化，不写值、不写路径，也不写哈希：哈希能反推出布尔字段的值。配置有变化时整次运行不通过，`--write` 什么都不写。
4. **`lsof` 检查有反向验证**：临时让剧本拉起一个持有宿主管道的孙进程，检查判了失败。
5. **schema 有两处不是纯附加**：结果取值多了三种，`config_files` 的条目形状改了。兼容报告的 schema 不属于冻结的协议契约，现在也还没有报告入库，可以接受。
6. **B 层录制没变**：显式传的 `default` 与适配器当前的模式一致，宿主不发 `set_mode`，所以任务书预计的 `config` 差异没有出现。解释成立，`gold_b` 9 个都通过。

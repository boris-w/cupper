# T185 `cargo xtask size`：按任务书的停止线报告行数

- 派发日期：2026-10-20
- 执行者：子 agent（测试工程师）。T090、T167、T091、T092 的执行者接着做（写过 `xtask ci e2e`）
- 分支：`chore/T185-xtask-size`
- 依赖：无

## 背景

守则第 8 条要求每完成一个模块就统计一次改动行数，一旦预计超限立即停下。今天有三个任务（T168、T169、T065）都是写完才统计，越过了停止线甚至硬停止线才发现。光在任务书里嘱咐不够，需要一个随手就能跑的工具，让统计变成一条命令。

## 范围

**做**：
1. **`cargo xtask size [--task <ID>]`**：
   - 统计当前分支相对于它从 main 分出的那一点（`git merge-base main HEAD`）的增删行数；
   - 口径与以往汇报一致：含测试，不含 lock 文件、生成物、`docs/`、`testdata/` 下的数据文件和截图基线。排除清单写成常量，并在输出里列出；
   - 编排者把 main 合进任务分支的合并提交不算任务自己的改动。用 merge-base 时合并带进来的改动会落在差异里，要说明怎样排除，例如按 `git log --first-parent` 只统计非合并提交，或者以最近一次合进来的 main 为基准。
2. **读停止线**：从 `docs/tasks/<ID>-*/brief.md` 读停止线和硬停止线。这两个数现在写在"## 规模"一节的自然语言里，例如"推算超过约 850 行……硬停止线 950"。
   - 解析不到时只报行数，并提示"任务书里没有找到停止线"；
   - 也可以提议在任务书模板里加一行固定格式（例如 `- 停止线：850；硬停止线：950`），连同解析一起做；
   - `docs/templates/` 里的任务书模板若要改，在本任务里一并改。
3. **输出**：
   - 一行摘要：增、删、净增，离停止线还有多少，或已超出多少；
   - 再按目录列出明细；
   - 接近停止线（例如到了 90%）或超过时，在摘要里醒目标出；
   - `--json` 输出同样内容，方便以后接进别的检查。
4. **单元测试**：口径的排除清单；merge 提交的排除；停止线的解析，含解析不到的情形。

**不做**：在 CI 里强制拦截超限（不同任务的上限经常由编排者裁定调整，先只做报告）。

- [ ] 单元测试覆盖上面三类。

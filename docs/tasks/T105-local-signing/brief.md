# T105 技术验证：Q35 本机签名身份

- 派发日期：2026-10-28
- 执行者：子 agent（原型实测工程师，偏安全）
- 分支：`spike/T105-local-signing`
- 依赖：T005、T073（都已合并；可以提前，计划 1.7）。结论即检查点 K7：通过则派 T162，不通过则维持退化模式

## 背景

用户暂不开通 Apple Developer Program，作者自用的构建没有 Developer ID，按现设计只能走退化认证（设计 5.8.1、5.13 Q35）。退化认证有两个代价：
- UI 只能用 `dev_key` 的双向证明校验宿主，UI 崩溃后新实例连不上还在运行的宿主，NFR-8 的"界面崩溃不影响会话"不成立；
- 沙箱外的同用户进程只要能杀掉宿主、再以注入的方式重新启动 App，就能接管。

Q35 要验证"本机签名身份"能不能补上这一点。两种来源：
- **A**：钥匙串里自建的代码签名证书；
- **B**：免费 Apple ID 在 Xcode 里得到的 Apple Development 证书。

签名要求在本机构建时写入，证书摘要或 Team ID 只存在本机构建配置里，不进仓库。通过的话新增"本机签名构建"（T162），并补设计和 ADR-05。

## 范围

**做**（计划 T105 一行和注的六项；安全"对两个问题的回答"第 1 题）。两种来源各做一遍，分别给结论：
1. **私钥隔离（通过条件）**：
   - 签名身份放在只装它的专用钥匙串里：有独立密码，不在默认搜索列表，签完即锁，访问控制每次确认；
   - 实测：同一用户的另一个进程在没有用户输入时用它签名，必须失败。钥匙串锁着时测一次，刚签完、还没锁时也测一次；
   - 这一项不通过，这个来源就判不通过，不用再往下测。
2. **负面矩阵**：用 5.8.1 的写法拟出这种身份下的签名要求串，以下都必须被拒绝：
   - 同名的自签名证书签的程序；
   - ad-hoc 副本；
   - 四个 Electron helper；
   - node；
   - 开发构建和 e2e 构建；
   - 同一身份签、但带 `get-task-allow` 或没开 hardened runtime 的程序。

   5.8.1 的要求串里有 `anchor apple generic` 和 Developer ID 的证书扩展，来源 A 显然不满足，写出两种来源各自可用的要求串。
3. **签名事实**：两种身份下各自需不需要 `disable-library-validation`；导出完整的 entitlements 和动态状态字。
4. **证书到期、撤销、更换**：宿主的行为，以及重新编译的步骤。
5. **脱敏**：Team ID 和证书摘要在 `--build-info`、审计日志、诊断包、录制里都经过脱敏；本机构建配置放在仓库之外，或主仓库的 `.private/`（不入库）。
6. **签名后的运行**：
   - 签名后能不能运行；
   - UI 被杀后，新 UI 能不能接上旧宿主；
   - CLI 能不能只读接入，并走完提权。

   要改宿主、原生扩展或 CLI 的签名要求才能验证的，在临时副本里改，补丁放在 `spikes/T105-local-signing/`，产品代码不动。

**不做**：
- 产品代码与正式的本机签名构建（T162）；
- 发布签名、公证（T180、T181）；
- 改设计和 ADR-05：结论交编排者，由编排者补设计，交用户确认。

## 约束（安全要求，必须遵守）

- **钥匙串和证书由用户操作**：
  - 建专用钥匙串、设密码、建证书或登录 Xcode，都由用户自己做；
  - 你写好逐步的操作说明，用 SendMessage 发给 `main`，由编排者转给用户；
  - 钥匙串密码不经过你：不出现在命令行参数、环境变量、文件和日志里，也不要请用户把密码发给你。需要输入密码的步骤，让系统弹框，或者由用户在自己的终端里运行。
- 不动用户的登录钥匙串和默认搜索列表；不导出私钥；不把私钥复制到别处。
- 实验结束后签名身份保留还是删除，由用户决定；删除步骤写进主仓库的 `.private/cleanup/T105-leftovers.md`（不入库）。子 agent 不删除。
- **仓库里不出现证书摘要、Team ID、证书名**，以及其他个人信息：Apple ID、用户名、本机路径。
  - 汇报和 notes 里用占位符；
  - 截图只截必要的部分，入库前过本机敏感词清单（主仓库的 `.private/sensitive-words.txt`）。
- 签名过的原型和构建只在临时目录里运行，不在真实项目上运行真实 agent（计划 1.10）。不运行真实的 Claude、Codex CLI；提权流程用假 agent。
- 不申请辅助功能、自动化、屏幕录制权限。

## 用户参与

是：在专用钥匙串里建证书或登录 Xcode，设置钥匙串密码，验证时按提示输入，需要用户在场（计划第 6 节第 10 行）。每一步用户要做什么、会看到什么提示，都写进发给 `main` 的说明里，一次发一组，不要让用户来回猜。

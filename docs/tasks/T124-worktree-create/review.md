## 逐项意见

1. **开工前定下的七项都照做了**：
   - 在途标记用 FULL 落盘的 `workspace.preparing`；
   - 单段短名和 `s-<id>`；
   - 后缀在创建时同步决定；
   - 仓库名和短哈希的取法；
   - `required` 过滤器回 `filter_unsupported`，失败后第一条消息进入暂停的队列；
   - 会话状态不进 `error`；
   - 进度只在单元用例里测。
2. **准备期间的调用先排着**：这是设计里漏掉的一条，执行者自己补上了。不排的话，后发的消息可能先开回合，并在还不存在的目录里 Attach。理由站得住，已写进 5.2.6。
3. **两段加锁**：等 1 秒的时候不占 `RepoLock`，不会挡住别的会话的暂存和提交。
4. **两条关键断言做过变异检查**：`mixed_changes` 只在本地模式下加；失败时回 `filter_unsupported`。

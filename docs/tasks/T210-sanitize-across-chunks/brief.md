# T210 脱敏与扫描：跨 chunk 的文本

- 派发日期：2026-10-30
- 执行者：子 agent（工程师）

- 依赖：T204、T110（都已合并）。T113 和以后入库真实录制的任务受益

## 背景

`tools/sanitize` 的脱敏（`sanitize`）和扫描（`scan`、`words`）都是逐帧、逐字符串做的。一条消息或一段思考在录制里会被切成很多个 `agent_message_chunk`、`agent_thought_chunk`，被切开的路径、名字在任何一帧里都不完整，于是扫不出来，也换不掉。

T110 在 Codex 的 s05 录制里就碰到一个：模型回答里的本机临时路径 `/var/folders/…/T/cupper-sp1.…/repos/…` 被切成约 35 块。直到 A 层金样例把同一条消息折叠成一行，`pii-scan` 才报出来。T110 已经手工改掉了 4 个副本，但工具本身还会漏。

## 范围

**做**（计划 T210 一行；设计 5.9.3）：
1. **脱敏**：在逐帧规则之外，把同一条消息的文本折叠起来再匹配。归组按会话加条目（`messageId`，或者工具调用的 id；没有 id 的，按相邻的同类 chunk）。
   - 匹配到时，回到原帧，把命中的各块改写成占位：第一块换成占位，其余命中的部分改成空串。帧数和 `seq` 不变，照 T110 手工的改法；
   - 用和逐帧规则同一套规则：路径、用户名、主机名、邮箱、令牌、`--terms` 的词表。
2. **扫描**：`scan` 和 `words` 也先折叠再匹配。命中时报原帧的文件和行号范围，不报命中的文本，照现有的规则。
3. **新增 UNIT-sanitize-across-chunks**：
   - 合成的录制：一个路径切成多块、一个词表里的词跨两块、一个令牌跨三块；
   - 断言脱敏后折叠起来不再命中，帧数和 seq 不变；
   - 扫描能报出来；
   - 做变异检查。
4. **全仓库复扫**：用新规则扫全部录制和金样例（`testdata/`、`spikes/`、`docs/tasks/*/data`），加主仓库的敏感词清单。命中的逐条处理：录制照第 1 条的改法，金样例重新生成，差异逐份说明。

**不做**：改录制格式；重写 git 历史。

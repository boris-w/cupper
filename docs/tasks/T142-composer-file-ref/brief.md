# T142 输入框增强 I：@ 文件引用与拖入文件

- 派发日期：2026-11-04
- 执行者：子 agent（前端工程师，ui-core 与桌面）
- 分支：`feat/T142-composer-file-ref`
- 依赖：T126（`files/search`、提示内容映射，已合并）。T145（输入框增强 II）依赖本任务

## 背景

T126 已经有 `files/search`：快照档的 `ls-files`，非 git 目录时遍历，带缓存和模糊匹配，返回 UTF-16 区间。T086 留好了输入框的扩展点：`composer/extensions/` 和 `OverlayContext`，附件条也已能显示 `file_ref`。本任务做 `@` 文件引用和拖入文件。

## 范围

**做**（计划 T142 一行；设计 5.7.4"输入框"、5.7.3 ShellAPI）：
1. **`@` 模糊搜索的弹出层**（Codex 样式）：
   - 在输入框里打 `@` 后弹出，挂在 T086 的 `OverlayContext` 挂载点；
   - 调 `files/search`，按返回的 UTF-16 区间高亮匹配的字符；
   - ↑↓ 选择，Enter 或 Tab 插入，Esc 关闭，插入后生成 `file_ref` 附件，或者内联引用（按 5.7.4 的设计）；
   - 结果为空、搜索失败、非 git 目录时各有提示，文案走 i18n。
2. **拖入文件生成引用**：
   - ShellAPI 以附加方式新增 `pathForFile`（ShellAPI 已冻结，只能附加）；
   - 主进程用 `webUtils.getPathForFile` 取路径；
   - 只接受工作区之内的文件，越出工作区的给出提示、不生成引用；
   - 拖入图片的处理属于 T145，本任务不做。
3. **安全**：
   - 文件名和路径只作为文本渲染，高亮按区间切片，不拼 HTML；
   - `pathForFile` 的路径由主进程取得，渲染进程不能自己拼一个路径塞进去。
4. **用例**：
   - E2E-file-ref（已登记）：`@` 搜索、键盘选择、插入，以及拖入文件生成引用；
   - 组件测试按需补充。
   - 基线只用 `ui-baseline` workflow 生成，逐张核对。
5. 附复刻度审阅截图（e2e 构建、系统字体，不进基线）。

**不做**：图片、斜杠命令、↑ 恢复、发送键（T145）。

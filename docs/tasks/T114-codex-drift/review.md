## 逐项意见

1. **拉取和比对分两步**：网络失败只会出在 `fetch` 里，判为"不确定"并重试；integrity 不符、漂移这类真问题只出在离线的 `drift` 里，不会被当成网络问题吞掉。和 license 作业的做法一致。
2. **比原型多做的两处**都是对的：
   - `params` 为 null 或 `anyOf` 的请求也算进闭包；
   - tagged union 的变体带上标签。没有它，0.165.0 里 `imageGeneration` 去掉 `result` 这一条会被别的变体盖住。
3. **已审阅的漂移**：每个新版本只报警一次，按"基线版本 + 漂移逐行原文"匹配；基线一旦重写，旧记录自然失效。这样 main 上的 nightly 不会因为一个已知、已有人跟进的版本天天报红，也不挡 T099。
4. **当天就抓到一处真实的不兼容**：codex 0.165.0 去掉了 `imageGeneration` 的 `result`，codex-acp 2.2.2 还在读，图像生成的结果会丢失。已记录，由 T113 跟进；已验证范围不动，仍是 ≤0.163.0。

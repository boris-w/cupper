## 逐项意见

1. **测法照设计，偏差都单列**：没有 `cupper:ready` 标记、启动不恢复当前会话、热启动在 e2e 构建上测不了（`dev_key` 只认拉起宿主的进程）、`next_needs_action` 没有处理方、输出延迟不含合并等待、场景 8 环境不合格，都写进报告第 3 节。
2. **数量级的问题追到了一段**：冷启动 p95 30–36 s，执行者加了分段计时，确认控制连接 2.4 s 内就绪，多出的时间全在窗口这一侧，再往下要靠渲染进程的分段标记（拆成 T262）。
3. **和机器快慢无关的问题单独拎出来**：翻页锚点 22/60 页位移 26 px，给了推测的位置（拆成 T263）。
4. **脚本问题都查到了根上**：seed 的请求 id 与 `initialize` 冲突；程序滚动被 T245 的"只有用户能让列表离开底部"复原，改为先发 wheel；`fs_usage` 以 root 运行，信号发给 sudo 传不到。这些写进了交接事项，T155 改写时不用再踩一遍。
5. **只在 runner 上测**：本机冒烟因为屏幕锁着没做成，第一轮 runner 当冒烟。

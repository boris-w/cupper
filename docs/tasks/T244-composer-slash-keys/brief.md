## 范围

**做**（计划 T244 一行；设计 5.7.4 输入框的"斜杠命令"和"↑ 恢复上一条"两条，2026-11-10 补写；5.7.7；PRD CP-1、CP-3）：

1. **斜杠命令菜单**：
   - 在文字开头输入 `/` 弹出菜单，挂在 T142 的弹出层上，和 `@` 列表共用。照 T142 的做法：从 `OverlayContext.area` 取文字区，加原生 keydown 监听，开头先判断 `keys.ts` 的 `composing()`（交接事项里 T145 那一行）。
   - 外观按设计 5.7.4 和 ui-spec 的"斜杠命令"：标题"斜杠命令"，`/` 之后的文字就是搜索词，没有匹配时写"没有命令"，最高 320 或 10 行。每行是 `/{name}` 和说明，有 `input_hint` 时一并显示。
   - 选中后把 `/{搜索词}` 换成 `/{name} `。按键和鼠标的选法跟 `@` 列表一致。发送时原样作为文本发出，不加协议字段。
   - 命令来源：
     - 已有会话：能力描述的 `commands`，随 `session.capabilities` 更新；
     - 新建会话页：`agents/capabilities` 的缓存，跟着所选的 agent。
   - 没有命令时不弹出。Codex 的"技能"分组不做。
2. **↑ 恢复上一条**：
   - 输入框为空（没有文字，也没有附件）、没有浮层时按 ↑，填入这个会话里用户最近发出的一条消息的文字，光标放在末尾。
   - 文字取自会话视图，所以重启后也有。附件、图片和评论不恢复。输入法组合中不处理。
   - 新建会话页什么也不做。
3. **发送键**：
   - "发送快捷键"偏好（`SEND_KEY_PREF`）T086 已经接上，Enter 和 ⌘Enter 两种都能用。
   - 这里要整理 `keys.ts`，让按键的判定给出"发送"还是"排队"：
     - 发送键：Enter，或 ⌘Enter；
     - 排队键：⌘Enter，偏好为 ⌘Enter 时是 ⌘⇧Enter。
   - M1b 在 T242 之前没有插话，运行中两种都排队，行为不变。T242 只需要把"发送"映射到插话。
4. **用例**（都已登记）：
   - **E2E-slash-commands**：用假 agent persona 给的命令。打开菜单、搜索、选中、发出，假 agent 收到的文本是 `/{name} …`；新建会话页也能弹出；没有匹配时显示"没有命令"。
   - **E2E-send-key-setting**：先设偏好，再验证：
     - 偏好为 ⌘Enter 时，Enter 换行，⌘Enter 发出；
     - 运行中按 ⌘⇧Enter 排队。
     - 偏好经 `ShellAPI` 的 prefs 设置，或者启动前写进 userData 的 prefs 文件。设置页的界面在 T147，本任务不做。
   - **组件测试**：
     - 菜单的搜索、没有命令时不弹出；
     - 弹出时 Esc 先关菜单（设计 5.7.4 Esc 的处理顺序第 1 条）；
     - ↑ 恢复的各项条件；
     - `keys.ts` 的发送和排队判定。
     - 放进 composer 现有的测试。要新编号先告诉 `main`。
   - 有新截图时，基线只由 `ui-baseline` 生成。

**不做**：
- 插话的按键和"跟进消息默认排队"（T242）；
- 设置页"通用"的界面（T147）；
- 斜杠命令在客户端的特殊处理（命令由 agent 解释）；
- ↑ 往更早的消息翻（只恢复上一条）。

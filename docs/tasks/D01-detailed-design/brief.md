## 范围（第 5 节应包含）

1. **仓库与工程结构**：
   - monorepo 的目录布局：Rust workspace 加 pnpm workspace，crates、apps、packages、protocol、tools 各放什么；
   - 构建命令；
   - CI 流水线：构建、测试、lint、schema 和生成代码的一致性检查、许可证门禁、iOS 编译检查。
2. **组件设计**：
   - 宿主内部的各个模块：网关、策略、会话编排、交互代理、事件存储、驱动层、Git 服务、文件服务、关注度与通知、运行时安装器、进程监护；
   - 桌面端：主进程、渲染进程的 ui-core、ShellAPI；
   - cupper-cli。

   每个模块写清楚：职责、对外接口、依赖、关键数据结构，以及并发模型（哪些是 actor、哪些用 channel、锁在哪里）。
3. **协议 v1 的草案**：
   - 方法清单，包括参数、结果、可能的错误码、是否需要幂等、需要什么 scope；
   - 事件类型目录；
   - 交互请求模型，包括选项 ID 到生效范围的对照表（SP-1 的结论）；
   - 会话能力描述；
   - 握手与版本协商；
   - 限额。

   只写契约，不写 Rust 代码。
4. **数据模型**：
   - SQLite 的表结构，包括主要字段、索引，以及哪些数据存在哪张表；
   - ID 的生成规则；
   - 保留与回收；
   - 迁移方式。
5. **关键流程**（用 mermaid 时序图）：
   - App 启动：拉起宿主、握手、首屏快照；
   - 新建会话，包括选择 worktree 的情况；
   - 发送消息、排队、插话（Steer）；
   - 审批先到先得；
   - 中断；
   - 崩溃恢复；
   - 升级；
   - 审查、暂存、提交。
6. **Agent 驱动层**：
   - 驱动接口；
   - Claude 和 Codex 各自的提取层：退出码、diff、运行状态、错误、计划；
   - 能力缓存；
   - 配置项映射；
   - CLI 的发现与版本检查；
   - 已知问题的规避清单，例如 Codex #556、取消后命令不停、并发 prompt。
7. **桌面界面结构**：
   - 窗口和布局，参照截图笔记；
   - 组件树；
   - 状态管理；
   - 快捷键；
   - 本地化和主题；
   - 安全加固的具体落点：fuses、CSP、命令白名单、原生确认框、真实输入检测。
8. **安全实现**：
   - 认证握手（固定令牌）；
   - principal 与 scope 的权限矩阵：命令 × principal；
   - 进程卫生；
   - 审计日志。
9. **测试策略**：
   - 单元测试和性质测试；
   - 用 SP-1 的录制文件驱动假 agent；
   - 端到端测试：Playwright `_electron` 加宿主加假 agent；
   - 兼容矩阵：适配器版本和 CLI 版本；
   - 金样例；
   - 性能预算。也写出 SP-6 的测试计划。
10. **构建与发布**：
    - 签名和公证；
    - Node 运行时和清单；
    - 在 electron-builder 和 Forge 之间**做出决定**；
    - 更新流程；
    - Electron 的最低版本。
11. **诊断**：日志的轮转和脱敏、诊断包。
12. **M1a 和 M1b 的范围划分**：
    - 两步各包含哪些组件和功能；
    - PRD 需求到组件的追溯矩阵，覆盖全部 M1 的 P0 需求。
13. **待定问题**：设计阶段还定不下来、需要在实现中验证的事项。

不做：不写产品代码，不拆具体任务（那是阶段 ③）。

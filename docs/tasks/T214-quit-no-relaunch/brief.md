# T214 确认退出后桌面不再拉起宿主

- 派发日期：2026-11-02
- 执行者：子 agent（TypeScript / Electron 工程师）
- 分支：`fix/T214-quit-no-relaunch`
- 依赖：无（T213 发现）。T099 依赖本任务

## 背景

T213 读代码发现（没有实测）：用户确认退出之后，桌面可能又拉起一个宿主。

- `apps/desktop/src/main/index.ts`：`before-quit` 里由 `QuitGuard` 决定退出，需要时经控制连接发 `host/exit`；`will-quit` 才调用 `host.control.close()`。
- `apps/desktop/src/main/host/control.ts`：`ControlConnection` 在 socket 的 `close` 事件里立即 `void this.connect()`，`#closed` 要到 `close()` 才置位。宿主不在时，`launcher.open` 会再启动一个宿主。
- 所以宿主按 `host/exit` 关掉连接时，`will-quit` 还没到，控制连接就会重连，可能拉起一个新宿主。新宿主会一直留到空闲退出。
- 窗口连接（T076 的桥）断开后会不会也重连、也拉起宿主，没有核对。
- 重启宿主（`restart`）的流程里，SIGTERM 让旧宿主关掉连接，`close` 事件触发一次 `connect()`；流程最后又显式 `await control.connect()`。两次连接会不会并存、会不会拉起两个宿主，也没有核对。

E2E-quit-confirm 只看原宿主的进程树是否消失，看不出这件事。

## 范围

**做**：
1. **先实测**：用 e2e（或主进程单元测试加假的 launcher）核实三件事：
   - 确认退出后，有没有新宿主被拉起（看数据目录里的 `host.lock`、宿主进程，或者 launcher 的调用次数）；
   - 窗口连接断开后会不会重连；
   - 重启宿主时会不会出现两次连接。
   每一件都写明结论和证据。
2. **修复**：只要决定了退出，主进程就不再重连，也不再拉起宿主；重启宿主只建一次连接。修法由你定，汇报里说明为什么这样修。
3. **用例**：
   - e2e 加一例：确认退出、宿主退出之后，没有新的宿主进程（数据目录里没有新的锁、没有新的宿主进程）。挂在已有的 E2E-quit-confirm 下。
   - 主进程的单元测试覆盖"决定退出后连接关闭不再重连"。挂在已有的编号下；需要新编号时先告诉编排者。
   - 能稳定复现的话，做修前修后对照（修前的用例失败、修后通过），写进汇报。
4. 在 runner 上用 `e2e-repeat` 把新的 e2e 用例连跑 100 次以上；要触发时把参数和提交发给 `main`。

**不做**：
- 不改宿主的退出流程和 5.8.1 的令牌比对。
- 不改 `QuitGuard` 的判定规则（什么时候问、问什么）。

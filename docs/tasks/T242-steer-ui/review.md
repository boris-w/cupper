## 逐项意见

1. **建在 T244 留的位置上**：`steers()` 只在运行中把发送键（或偏好打开时的排队键）判为插话，空闲时行为不变；`useSessionSend` 让输入框、发送按钮和 RP-12 走同一条路径。
2. **能力、回退和"迟迟没有回复"都有着落**：不能插话时排队并只提示一次；回退每次 toast；回复不来不卡输入框，1 秒后才显示等待提示，避免正常插话时闪一下。
3. **e2e 的修正查得深**：插话发在回合的 `Preparing` 期间会被宿主按 `not_prompting` 排队；执行者还发现"回退"那条原来是因为同一原因才过的，并没有测到 `steer_error`。改成等 agent 拿到这一轮的 prompt 再插话，两条都走到了该测的路径。
4. **E2E-reject-with-message 的调整合理**：默认改为插话后，打开"跟进消息默认排队"保留对排队路径的验证，插话路径由新用例覆盖。

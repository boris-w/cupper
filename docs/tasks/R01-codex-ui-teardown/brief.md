# R01 Codex 桌面客户端 UI 拆解

- 派发日期：2026-10-16
- 执行者：子 agent（产品调研）
- 分支：`research/R01-codex-ui-teardown`
- 依赖：无

## 背景

用户的第一个需求是复刻 Codex UI，做一个桌面 agent 客户端，底层用 ACP 协议接入 Claude Code 和 Codex。复刻 UI 是这个需求的关键。写 PRD 之前，需要完整了解 Codex UI 有哪些功能、长什么样、怎么交互。见 `docs/meetings/2026-10-16-prd-interview-1/minutes.md`。

## 目标

完整拆解 OpenAI Codex 桌面 App（Codex app）的 UI 和交互，产出一份可以直接用来划定复刻范围的功能清单。

## 范围

- 做：
  - 信息架构：窗口结构、侧边栏、项目和会话（thread）的组织方式、主要区域划分。
  - 会话界面：输入框（附件、@ 文件、斜杠命令等）、消息流中各类内容的呈现方式（文本、推理过程、命令执行、文件修改、diff、计划/待办、错误）。
  - 审批与权限：命令和文件修改的审批交互、权限或沙箱模式的切换。
  - 运行模式：本地 / worktree / 云端等模式的区别和切换方式。
  - 代码审查：diff 查看、review、提交或 PR 相关的界面。
  - 其他功能：模型和推理强度选择、终端、skills、automations、设置页等。
  - 视觉风格：布局、配色、字体、亮色/暗色模式、动效特点。
  - 快捷键和关键操作流程（从新建会话到合并改动的完整路径）。
  - 与其他 Codex 形态（IDE 插件、网页版 chatgpt.com/codex、CLI）的区别，只需简要说明。
  - 技术线索：App 用什么技术构建，哪些部分开源（例如 openai/codex 仓库中的 app-server 协议），许可证是什么。
- 不做：不写代码，不做技术选型建议。

## 验收标准

- [ ] 功能清单表：功能 / 描述 / 复刻优先级建议（P0 核心、P1 重要、P2 可后置）/ 来源链接。
- [ ] 至少一条从新建会话到完成改动的完整交互流程描述。
- [ ] 视觉风格要点。
- [ ] 每条事实都有来源（官方文档、博客、发布说明、开源代码、可信评测）。区分"已核实"和"推测"。
- [ ] 注明资料的时效（发布或更新日期）。
- [ ] 「对架构的启示」一节：从"桌面端先行、移动端平滑接入"的角度，说明这些发现对整体架构意味着什么（作为 PRD 产品-架构对齐会的输入）。

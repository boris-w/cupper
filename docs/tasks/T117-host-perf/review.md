## 逐项意见

1. **样本走文件，不走 stdout**：`perf::record` 写到 `CUPPER_PERF_OUT`，只在测试和 `test-harness` 构建里编译。不打乱 libtest 的输出，PERF-snapshot 也改用同一个出口。
2. **用例不断言绝对预算**：按设计 5.9.6，绝对预算只在参考硬件上判定。夜间作业只看趋势：p50 超过同一指标、同一机型历史中位数的 1.5 倍判为退化。只比同一机型是对的。
3. **测量方法**：冷启动从拉起宿主进程算到拿到完整的索引快照，连接每 1 ms 重试一次，轮询间隔不影响计时；内存在 6 个会话同时跑带输出的回合时采样。前两项的数据用 `test/seed` 灌 200 个会话。
4. **第一批数字都在预算内**：冷启动 p95 26 ms（预算 400 ms），索引快照 p95 2.9 ms（预算 50 ms），内存 p95 43 MiB（预算 64 MiB）。
5. **两项评估**：
   - `flood_mixed`：慢在宿主。不能合并的事件逐个提交，约 0.87 ms 一个；设计里没有条目吞吐的预算，真实 agent 的速率离这个上限很远，算达标。
   - 指纹遍历：10 万文件约 43 ms，每回合两次约 86 ms，在快照预算内。数据和理由写在 `notes.md`，认可暂不改。

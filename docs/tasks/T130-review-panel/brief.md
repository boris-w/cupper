## 背景

Git 服务已经齐了读的一侧（`git/diff` 四种范围、`git/file_diff`、`git/status`、`git/branches`）和仓库档的写操作（`git/stage`、`git/unstage`、`git/revert`）。T130 在侧边面板的"变更"标签里做审查面板的主文档部分；diff 视图本身由 T131 放进独立源的 iframe，这里只留接口。设计 5.7.4、5.7.5 的"审查面板"、5.7.8 的 RP-11 已定样式和安全约束（Codex 样式）。

关于 T123：`git/commit`、`git/push` 的协议在 M1a 已冻结，提交弹窗按协议类型和 mock 宿主先做；T123 合并后在真实宿主上接通。如果你做到提交弹窗时 T123 还没合并，先做其余部分，提交弹窗的接通放最后，并告诉 `main`。

## 范围

**做**（计划 T130 一行，第 3 节"T130（L）"的注）：
1. "变更"标签的头部："查阅来源"范围下拉（未暂存、已暂存、最近一回合等）、增删统计、文件树开关、选项菜单的 M1 项（换行、diff 视图、展开收起全部、刷新）。
2. 文件树：默认关闭、⌘⇧E、筛选、Git 状态图标、右键菜单。
3. hunk 与文件操作的图标按钮；底部整组操作的药丸（还原全部、暂存全部；"已暂存"视图里是取消暂存全部，没有还原全部）。
4. 还原确认控件（RP-11）：真实输入、500 ms 待命期、不提供"不再询问"；由"还原全部"触发时默认焦点在"确认"，由审查文档触发时不自动获得焦点，同一时间只显示一个。
5. "Git 操作"菜单与提交弹窗："包含未暂存的更改"，提交、提交并推送、推送；hooks 与指纹提示（用户档，`repo_config_changed` 时确认文案带上）。
6. `caveats`（`mixed_changes`、`late_tool_effects`）的提示、空状态。
7. 行内评论的草稿由主文档持有，进入输入框的附件条（GT-2）；为 diff 视图（T131）留接口。
8. 面板各部分共用同一个 `diff_token` 和选择状态。
9. 用例：UNIT-review-actions、UI-review（文件树开合、整组操作在三种范围下的状态、空状态），都已登记。截图基线只用 `ui-baseline` workflow 生成（5.1.6）。
10. 附复刻度审阅截图（e2e 构建、系统字体，不进基线）。

**不做**：diff 视图与审查文档 iframe（T131）；回合改动卡片（T132）；worktree 相关（T124、T125）。

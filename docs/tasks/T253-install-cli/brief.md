## 范围

**做**（计划 T253 一行，v1.3.92 由 T147 拆出；设计 5.7.4 设置页、5.10.1 的 CLI 位置、5.7.2 的 `privileged`、5.7.8；P-6）：

1. **`PrivilegedAction` 附加 `install_cli`**（ShellAPI 只做附加），由主进程执行：
   - **位置检查**：先检查 App 在"应用程序"文件夹里；不在就说明原因，不装。从 DMG 或下载目录直接运行时，链接会指向一个随时会消失的位置。
   - **目标**：默认 `~/.local/bin`，没有就建；链接名按构建种类取（发布构建是 `cupper`，其余带构建种类的后缀，按 5.7.9 的 CLI identifier 推出，具体写法你定并在汇报里说明）。
   - **建符号链接**：指向 `Contents/Helpers/cupper`（5.10.1），不经 shell。
   - **不覆盖用户自己的文件**：同名文件已存在、又不是指向本 App 的 CLI 时，说明情况，不覆盖。已经指向本 App 的 CLI 时算已安装。
   - **原生确认框**：说明要在哪里建什么链接。
   - 走 `requestPrivileged` 的通用规则：真实输入、同一时间只弹一个确认框、取消后的冷却。
2. **设置页加"命令行工具"一页**：
   - 在分页表里加一行（`{ id, Body }`，T248 定下的形状），位置按设计 5.7.4 的分区顺序排在最后。
   - 页里一行说明加一个按钮，复用 `CommandButton`。安装后显示链接的位置。
   - 退化模式下 CLI 照常按 uid 只读接入，入口不隐藏（计划 T147 原来的一行）。
3. **自用构建的安装说明**：`docs/user/` 里目前让用户手动 `ln -s`（交接事项里 T160 那一行），改成指向设置页。
4. **用例**：
   - **UNIT-install-cli**（已登记）：在临时目录里测位置检查、链接名、不覆盖、已安装的判定。
   - **组件测试**：按钮的状态和结果提示。
   - 截图：如果要给这一页加截图，并进 `settings.spec.ts`，基线只由 `ui-baseline` 生成。

**不做**：
- 卸载命令行工具；
- 自定义安装目录（M1 只用默认目录）；
- 其他设置页（T147）。

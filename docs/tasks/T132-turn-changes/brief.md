# T132 回合改动卡片与撤销

- 派发日期：2026-11-04
- 执行者：子 agent（前端工程师，ui-core 与桌面）
- 分支：`feat/T132-turn-changes`
- 依赖：T130（审查面板与还原确认控件）、T146（回合折叠），都已合并。T148 依赖本任务

## 背景

回合结束时宿主会拍结束快照，`snapshot.recorded` 带上 `stat`（5.3.5）；`git/diff` 的 `{turn: id}` 范围能取到这个回合的改动。

- T146 刚合并了回合折叠，"始终显示"的名单是 `rows/flatten.ts` 里的常量 `ALWAYS`，改动卡片要加进去；
- T130 的还原确认控件（RP-11）在审查面板里，"撤销"复用它。

## 范围

**做**（计划 T132 一行；设计 5.7.4"回合改动卡片"、5.3.5、GT-3、F3）：
1. **改动卡片**：回合结束、并且结束快照的 `stat` 有改动时，在最终回答之后显示：
   - 标题行"{n} 个文件已更改 +a −b"；
   - 每个文件一行，文件列表来自 `git/diff` 的 `{turn: id}` 范围；
   - 点某个文件：在侧边面板打开"变更"，切到这个回合的范围，滚到这个文件（用审查面板 store 的 `focus`）；
   - 卡片显示在回合折叠之外（加进 `ALWAYS`），放在最终回答之后。
2. **撤销**：
   - 经主文档的确认控件（真实输入、500 ms 待命期，RP-11），以这个回合范围的 `diff_token` 调用 `git/revert`；
   - 补丁应用失败（`stale_diff`）时给出提示，并提供打开审查面板的入口；
   - `lfs_object_missing`（T237）时提示"在终端里运行 `git lfs fetch`"。
3. **快照不完整**（`snapshot.recorded` 的状态不是完整）：卡片注明原因，不提供撤销。
4. **用例**（都已登记）：
   - UI-turn-changes：卡片的显示，包括折叠时也在、快照不完整的样子，亮暗两种主题；
   - E2E-turn-changes-undo（nightly）：撤销走确认控件，回合的改动被还原。
   - 基线只用 `ui-baseline` workflow 生成，逐张核对。
5. 附复刻度审阅截图（e2e 构建、系统字体，不进基线）。

**不做**：审查面板本身（T130 至 T238）。

## 逐项意见

1. **`--force` 只越过一条检查**：`worktree add --force` 本来也会越过"分支已在别处检出"。宿主在 add 之前，先在 `worktree list` 的记录里自己查（排除这条路径自己的记录），再 unlock、add。两项检查各有变异测试证明，去掉任一项用例都会失败。
2. **不碰用户的记录**：只在锁是本会话的或没有锁时才重建，不执行 `worktree prune`。
3. **新建、崩溃接管、恢复走同一段 `add`**，三条路径不会分叉。
4. **只读会话**：写调用的拒绝范围和已归档会话相同，`session/get` 照常回答。
5. **`project/remove` 先问遍再动手**：部分归档的问题基本消除，留下一个很小的窗口，见下文。

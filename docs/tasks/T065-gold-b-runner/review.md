## 逐项意见

1. **进程内 agent 的入口只在 `test-harness` 构建里**：`test_config.in_process` 不参与反序列化，只能在测试进程里起宿主时设置。`Instance.group` 改为 `Option`，进程内实例没有进程组、不写 `adapters` 行，运行时里发信号、采样的五处都要先拿到进程组才能进入，从源头上排除了 0、1、-1 和本进程组号。单元测试走完停止的四个截止时间（8 s）一个信号都不发。比裁定要求的更彻底。
2. **同步依赖 SDK 的按序分发**：先写了用例证明（50 条通知加一个应答后发未知请求，回复到达时邮箱里正好 50 条），用例与 `Run::sync` 的注释都写明依赖 SDK 3.3.0，换 SDK 时这条用例会先失败。
3. **规范化依据 `schema::document()` 的注解**，不另写字段清单；联合类型选错分支导致本机临时目录进金样例的问题，执行者自己发现、改正并补了用例，`tools/sanitize scan testdata` 为 clean。
4. **每写一帧都同步一次**：同一 `t` 的帧也逐帧处理，金样例才稳定。原因是宿主内部 `session/new` 的应答与紧随的 `available_commands_update` 在会话 actor 里走两个通道，见"记下的点"第 1 条。
5. **用户命令从录制推出**，只有四种，不另写命令文件，没有多一种格式。
6. **接入**：`pnpm test:golden` 跑 A、B 两层，`xtask` 的 `rust` 作业加了 `golden` 步骤，有单元测试核对；`xtask ci` 原有的"设置了 `UPDATE_GOLDEN` 就拒跑"照样守住 CI 里不会改写金样例。
7. **设计 5.9.3**：执行者列的十条规则，编排者已补进设计（`137ea5e`）。

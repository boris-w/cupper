## 范围

**做**（计划 T099 一行、1.8 的"M1a 退出"、5.12.2）。下面所有运行都在**同一个退出候选提交**上：

1. **nfr1 连跑 20 次**：
   - 在 GitHub 的 macOS runner 上，用 `e2e-repeat` 对 `src/nfr1.spec.ts` 全部用例连跑 20 次，全绿才算；
   - 并行度同 CI 设定，不允许重试、跳过或隔离；
   - 失败一次就查明根因，修复另开 fix 任务（由编排者定），计数清零。
2. **降速变体 5 次**：运行期间占用一半核心的负载进程，或者降低优先级。
   - `e2e-repeat` 现在没有这个选项，给它加一个输入；负载只在 runner 上跑；
   - 5 次全绿才算。
3. **`xtask ci pr` 与 `xtask ci nightly` 各通过一次**：
   - `pr`：候选提交推到 main 时 `ci` workflow 的 8 个检查；
   - `nightly`：编排者在候选提交上手动触发 `nightly.yml`；
   - 两者的结构化摘要从构件里下载，用来做第 4 条的核对。
   - PERF 闸门不上 CI，由编排者在作者机器上跑 `xtask ci nightly` 的 `perf` 作业。时间由用户定，运行期间不操作机器；结果交给你写进记录。
4. **核对**：
   - UNIT-unsupported-set 通过；
   - `node tools/trace-ids/src/main.ts verify --milestone M1a`，用第 3 条的摘要，只用同一个提交的结果：M1a 的待完成登记为空；不为空的逐条列出原因；
   - 契约已冻结：`schema-compat` 和 ShellAPI 快照在 `protocol` 作业里通过；
   - COMPAT 编号按入库的兼容报告推导（T202 的报告全部通过）；
   - MAN 编号按入库的证据。
5. **写记录** `docs/tasks/T099-m1a-exit/record.md`：
   - 候选提交、各次运行的链接和结果、摘要的要点；
   - 本机替代不了的缺口，交用户确认：macOS 14、15 的对端校验已由 nightly 覆盖，写明是哪次运行；CI 负载下的稳定性由第 1、2 条覆盖；其他你发现的缺口；
   - M1a 同步会的议程草稿：做了什么、遗留什么、M1b 第一波（计划 4.2 的 B1）。

**不做**：修复新发现的失败。照 1.8 的规则，查明根因后停下汇报，由编排者另开 fix 任务。

## 关键取舍

- **契约冻结排在测量闸门之后（P-1）**。5.12.5 说"协议 crate 合并时冻结"，5.7.1 和 Q33 说"后备方案的协议改动落在冻结之前"。闸门要用到真实宿主和 windowBridge（第 8 波），所以两句话无法同时成立。我选择后者：这样也能在 M1a 实现过程中修正契约。Q33 的改动是附加式的，如果想按原文提前冻结也可以，T016 只需改依赖。
- **压短 M1a 关键路径**：第一版的关键路径落在"提权 → CLI 命令 → 兼容套件"上。我调整了三处依赖：
  - 兼容套件只依赖 CLI 库，不需要 `elevate`；
  - 会话 actor 经接口通知索引，不等 T034；
  - 录制导出并进测试接口任务 T047，这样 T064 和 T065 可以并行。
- **不写桩代码**：宿主对未实现的方法统一返回 `unsupported`。M2 和 M3 的方法在 M1 结束时本来就是这样，所以按依赖顺序合并不需要临时代码。Q8 的后备方案只在不通过时实现（P-7），避免留下没人用的代码。
- **界面任务不等测量闸门**：ui-core 只依赖 ShellAPI 和 HostPort，闸门不通过时它不受影响。另外建议 T076 先用 TS mock 宿主做一次预测量。
- **拆分 M1b 超上限的任务**：输入框、消息流、设置页、端到端第一版都超过上限，各按功能拆成两个 M。
- **任务表、依赖图、波次和进度清单出自同一份任务数据**，生成脚本放在会话临时目录里，没有进仓库。之后手工改 `03-plan.md` 时，需要自己保持四处一致。

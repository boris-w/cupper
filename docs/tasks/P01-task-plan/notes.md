1. 通读 `02-design.md`、`design/` 全部 13 个文件、PRD 第 5–7、10 节、ADR-01 至 ADR-11、两份会议纪要，以及 SP-1、SP-4a、SP-4b 的报告和 `spikes/` 下的代码规模（SP-4a 约 7,000 行 Rust，用来估计迁移类任务的规模）。
2. 先按 5.12.2、5.12.3 的每一行列出工作项，再按"一个任务一个子 agent、上限约 1,500 行"切分，按 CODEOWNERS 式的区域标注。
3. 任务表、依赖图、波次和进度清单由同一份任务数据生成，保证四处一致：
   - 依赖只保留直接依赖（传递约简）；
   - 波次是"所有前置都在更早的波次"的最早层次；
   - 关键路径按规模加权（S=1、M=2、L=3），松弛为零的任务在表里加粗；
   - M1b 的任务除"可提前"的以外都隐含依赖 T099。
   生成脚本放在会话的临时目录里，没有进仓库：之后编排者手工改 `03-plan.md`（例如打勾、调依赖）时，需要自己保持表、图、波次一致。
4. 关键路径第一版落在"提权 → CLI 命令 → 兼容套件"一线上。调整了三处依赖，使它反映真实的先后关系：兼容套件只用 CLI 库，不需要 `elevate`（T064 不再依赖 T046）；会话 actor 经接口通知索引，不等 IndexActor（T043 不再依赖 T034）；录制导出放进测试接口任务（T047），让兼容框架和 B 层运行器可以并行。调整后 M1a 有三条几乎等长的关键链。

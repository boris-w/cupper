# SP-5 Git 快照与审查操作实测

- 派发日期：2026-10-16
- 执行者：子 agent（后端工程师）
- 分支：`spike/SP-5-git-snapshot`
- 依赖：无

## 背景

PRD v1.0 要求审查面板以仓库的实际 Git 状态为准（GT-1），支持按文件或 hunk 暂存、取消暂存、还原（GT-3），以及最小 worktree（CP-5）和安全清理（GT-5）。"最近一回合"的 diff 定义为宿主在回合开始和结束时记录的两次工作区快照之间的变化。对齐会建议用"临时 index + `write-tree`"来拍快照（见 `docs/meetings/2026-10-16-prd-arch-alignment/architect.md` 议题 3.2、5.2 中的 SP-5）。本实测为 ADR-10（Git 与 worktree）提供依据。

## 目标

在真实的大仓库上验证这些 Git 操作的正确性和耗时，给出 ADR-10 的建议。

## 范围

- 做：
  1. **回合快照**：不触碰用户的 index 和工作区，用临时 index（`GIT_INDEX_FILE`）加 `git add -A` 加 `git write-tree` 拍下工作区的完整状态，包括未跟踪文件，并遵守 .gitignore。测量耗时，看文件数和改动量的影响。顺带比较其他方法，例如 `git stash create`，说明各自的缺点。
  2. **快照之间的 diff**：两次快照 tree 之间的 diff，以及快照与当前工作区之间的 diff。确认能拿到文件列表、统计和逐 hunk 的内容。
  3. **按 hunk 暂存、取消暂存、还原**：生成单个 hunk 的补丁，用 `git apply --cached`（暂存）、`git apply --cached -R`（取消暂存）、`git apply -R`（还原工作区）实现。逐一验证这些边界情况：新文件、删除、重命名、二进制文件、权限位变化、CRLF、文件末尾没有换行、同一文件多个 hunk、补丁与当前状态冲突。
  4. **worktree**：基于指定分支创建带新分支的 worktree（`git worktree add -b`），测量耗时；检测 worktree 中有没有未提交、未推送的内容，作为安全清理的判断依据；测试清理和用分支重建 worktree。
  5. **边界**：子模块、Git LFS、超大文件、嵌套仓库；说明哪些情况只能降级处理。
  6. **实现方式对比**：调用 git 命令行，还是用 libgit2 或 gitoxide 这类库。从正确性、性能、功能覆盖（hunk 级操作、worktree）、分发成本几方面比较；结论以实测为主，有资料作补充。
- 不做：
  - 不写产品代码，不设计宿主接口。
  - **不碰用户机器上任何已有的仓库**，包括本仓库的工作区。

## 测试环境

- 在 worktree 之外新建临时目录，浅克隆一个文件数不少于 5 万的公开仓库（例如 linux 或 kubernetes），作为大仓库样本。另外自己构造小仓库，用来测边界情况。
- 记录测试机器的 git 版本、macOS 版本、CPU 和磁盘类型。

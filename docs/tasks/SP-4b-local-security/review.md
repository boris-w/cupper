### 带入 ADR 的事项

- **ADR-05**：方案 1 成立，不需要换成 XPC。但必须补上以下几点：
  - 固定令牌握手：accept 时校验，用 nonce 挑战，之后每条消息都比对令牌；
  - 发布构建的签名要求里加上 Developer ID 的标记 OID；
  - 用动态状态字检查签名标志；
  - 开发构建和自行构建必须用继承 fd 传一次性密钥；
  - UI 的 fd 设置 CLOEXEC；宿主拒绝 SCM_RIGHTS；
  - "沙箱能挡住连接"这句话要加前提条件；
  - 不在 argv 和环境变量里放任何秘密。
- **ADR-01**：
  - "宿主退出之后再安装"有了实测依据；
  - 新增宿主自检：比对运行中的 cdhash 和磁盘上的 cdhash；
  - 新 UI 校验旧宿主时遇到 -67034 或 ENOENT，当作"等待退出"；
  - 安装器不能原地覆盖可执行文件；
  - 运行中不读取包内的任何资源；
  - 撤销"把宿主复制到包外"这个后备方案。
- **ADR-08**：官方 Node 二进制带着去掉注入防护的 entitlement，Node 里永远不跑可信代码。

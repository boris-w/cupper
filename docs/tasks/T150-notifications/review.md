## 逐项意见

1. **先补验再动手**：T101 留下的问题在开工前用原型补验，结论支撑了"照原设计做"，不必改由 LaunchServices 拉起宿主或启用 T158。
2. **退出事件的回归查得好**：宿主一旦被当成 App，注销、关机和活动监视器的"退出"会让 AppKit 当场 `exit(0)`，跳过有序退出。改跑 NSApplication 是本任务带来的，在本任务里接管，和 SIGTERM 走同一条路。
3. **不碰本机的 LaunchServices**：test-harness 和 e2e 构建不登记；真实登记的测试只在 runner 上跑，本机的 `cargo xtask ci` 直接返回。
4. **图标的裁定有依据**：T101 的记录表明通知中心只在第一次连上通知服务时读取名称和图标，T150 不调用通知接口，先不写图标没有风险，也不留以后要扔的东西。
5. **拆分守住了"合并时有人用"**：主循环、登记和名称都在本任务里生效，UserNotifications 和 NSWorkspace 的接口留给真正用它们的 T250、T251。

## 逐项意见

1. **图标在接入通知之前进包**：名称和图标在 helper 第一次连上通知服务时被记下，本任务把图标和 UserNotifications 放在一起，顺序对。icns 由可重复运行的脚本生成，产物哈希稳定。
2. **通知守住了 5.7.8 和 5.2.9**：不设 category（没有操作按钮）、没有声音；正文只用按原因选的内置文案，不放 agent 原文；关掉开关时不弹，但意图照写。
3. **授权时机有理由**：启动时用户在电脑前，等到第一次要弹时再申请，授权框会在用户不看窗口时弹出；被拒后不再申请。只在发布、自用、开发构建申请，测试构建不碰通知服务。
4. **意图的标题和请求类别取状态核心的摘要**：视图要等这一批写完才更新，取摘要才能在刚进入 `needs_action` 时就知道是"批准"还是"回答"。

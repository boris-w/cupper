## 逐项意见

1. **原型验证的就是产品的配置**：直接 import `apps/desktop` 的协议注册、CSP、webPreferences 和 inputGuard，没有另写一份。结论可以直接用于 T131。
2. **功能项都有证据**：constructable stylesheet、跨源的 module Worker 和模块脚本、违规为 0、跨源隔离、注入按文本显示、只认第一个端口、导航拦截都有证据；30 次之间结果一致。
3. **8 点逐一给了结论**：
   - 菜单加速键在焦点位于 iframe 时照样生效，这是在 runner 上用真实按键测的；
   - inputGuard 不借用 iframe 里的输入；
   - 剪贴板没有闭环：写入成功，但读回对不上。如实列为 T131 的 e2e 核实项，不影响 K9：写入路径、权限处理器和焦点规则都已验证，没对上的只是读回这一步。
4. **性能只记录**：滚动 p95 18.7 ms，略高于 5.9.6 的 16.7 ms，但这是共享 runner；审查文档的渲染进程约 300 MB，在 600 MB 上限之内。高亮要 2.5–3 s，靠预加载解决。没有数量级的问题。
5. **两条对 T131 很关键的发现**：
   - Virtualizer 必须就是滚动容器，否则全量进 DOM，约 800 MB；
   - 测试输入有两条路径：inputGuard 看得到的那条送不进 iframe，能送进 iframe 的那条 inputGuard 看不到。

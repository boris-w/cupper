## 背景

T003 在 Claude 上验证了 Q8 和 SP-4b 遗留第 7 条（K1 已通过）。Codex 的部分留给本任务，要在 M1b 写 Codex 驱动（T111）之前测完：
- **Q8（Codex）**：同一个 codex-acp 进程上，多个会话同时发 prompt 是否可靠。这是 ADR-09"每种 agent 共用一个适配器进程"对 Codex 的前提。不通过时启用后备 T119：Codex 的 prompt 全局串行，或只对 Codex 退回每个会话一个适配器进程。
- **SP-4b 遗留第 7 条（Codex）**：codex-acp 拉起工具命令时，命令有没有自己的会话和进程组（setsid）。这关系到提权的血缘检查（5.8.4）和关闭时回收命令（K21）。
- **Q31**：codex-acp 是否经 `_meta` 透出 `agentMessage.phase`。透出就以它为准判定最终回答，否则用宿主的规则（5.3.5）。
- **Q25（初查）**：Codex 权限模式的完整取值和档位。

用户已许可本任务使用真实的 Codex CLI，会消耗额度（2026-10-28；计划第 6 节第 9 行）。

## 范围

**做**：
1. **Q8（Codex）**：
   - 用 SP-1 的 TS 客户端（`spikes/SP-1-adapter-behavior/`）编写并发剧本，可以复用 T003 的剧本（`spikes/T003-tech-validation/`）；
   - 通过条件同 5.9.5：两个会话同时各发 3 个 prompt，全部在 5 分钟内返回，输出没有串到另一个会话，重复 3 轮；
   - 记录每一轮的数据；
   - 同 T003，再测一个会话的审批挂起时，另一个会话是否照常运行。
2. **SP-4b 遗留第 7 条（Codex）**：让真实 agent 执行一条会持续几秒的命令，观察进程树：命令的会话 ID、进程组是否与 codex-acp、app-server 相同。
3. **Q31**：在录到的帧里核对 `agentMessage.phase` 是否经 `_meta` 透出，写明字段的位置和取值。
4. **Q25（初查）**：
   - 列出这一版 codex-acp 公布的权限模式取值，以及 `revise_plan` 是否结束回合；
   - 只记录观察，不改对照表和档位表（M1b 的 T110 做）。

适配器用运行时清单锁定的 codex-acp 2.2.2（`runtime/manifest.json`）。顺带记下当天的最新版本，供以后升级参考，不升级。

**约束**（安全要求，必须遵守；计划 1.10，P-14）：
- 临时 git 仓库放在每个用户自己的临时目录下，不用作者的任何真实项目。剧本固定，不让模型联网取内容。
- 权限模式显式设为 `read-only` 或 `workspace-write`；只选不持久的选项，不选任何"总是允许"类选项。
- 用最便宜的模型。
- **运行之前**，用 SendMessage 问 `main`：用户是否已经把 `~/.codex/config.toml` 和 `~/.codex/hooks.json` 备份到仓库外（0600）。没得到确认之前，不运行真实的 Codex。
- **运行前后做哈希对比**：`~/.codex/config.toml`、`~/.codex/hooks.json`。
  - 报告里只写文件名、表名和"是否变化"，不写值；
  - 新增的 `[projects]` 信任项单独列出：只写条数，以及它们是不是本任务的临时目录；
  - 由用户决定保留还是恢复。
- 不读写 `~/.codex/auth.json`。除了上面的哈希，不读 `~/.codex` 下的其他内容。不用隔离的 `CODEX_HOME`：要等 Q30 确认刷新令牌不会轮换（P-14）。
- **不修改任何用户配置**。Codex 运行时自己写入的会话记录等，列成清单写进主仓库的 `.private/cleanup/T102-leftovers.md`（不入库），由编排者请用户确认后再清理。子 agent 不删除这些内容。
- 作者机器上的 Codex 走自定义网关，常因过载重连（SP-1）。
  - 结果"不确定"时可以重跑，每项最多重跑 3 次，每次都记下来；
  - 网关的域名不能出现在入库的任何文件里。
- 外发请求不带个人信息，需要时用 `cupper-research` 作占位。录制或日志里如果出现用户名、本机路径、会话 ID、网关域名，入库前先脱敏，方法同 SP-1；入库前过本机敏感词清单（主仓库的 `.private/sensitive-words.txt`，用户在建）。
- 负载：两个会话的剧本本身不重，不在本机并行跑多份。

**不做**：
- 产品代码。原型代码放在 `spikes/T102-codex-validation/`，产品代码不依赖它。
- Codex 的兼容套件（T113）、提取层与对照表（T110）。

# T256 消息流的滚动条、底部间距与发送后回到底部

- 派发日期：2026-11-10
- 执行者：子 agent（前端，ui-core；T245 的执行者）
- 分支：`fix/T256-stream-scroll-gap`
- 依赖：T245（已合并）

## 来由

用户试用自用构建时发现三处问题（2026-11-10，截图没有入库）：

1. **往上翻之后发消息，列表停在原处。** 用户发消息就是要看这条消息和 agent 的回应。Codex、ChatGPT 都是发送后回到底部。
2. **滚动条位置和样式不对。** 滚动条落在内容栏的右边缘，压住了行尾的"查看后续输出"，样式是系统默认的粗滚动条。
3. **消息流和输入框之间没有间距。** 最后一行（例如"取消后仍在运行：Terminal"）紧贴输入框，被输入框的阴影压住一部分。

## 范围

**做**（计划 T256 一行；设计 5.7.4 会话区、长会话的两条滚动规则，5.7.10）：

1. **发送后回到底部**：
   - 用户经输入框发出消息（新回合、插话、排队都算）后，列表回到底部并恢复贴底。
   - 这是 T245 "只有用户的操作能改变贴底状态"的反方向，用同一套意图机制表达，不另起一套。
   - 排队消息行上的"插话"也算。
   - 宿主自己开的回合（例如队列出队）不算用户操作，不跳。
2. **滚动条**：
   - 滚动容器占满会话区的宽度，滚动条贴在会话区最右侧；内容栏仍按现在的最大宽度居中。
   - 样式改成细的悬浮式：只在滚动或悬停时明显，颜色用 token。
   - 先看 ui-spec 和本机 Codex 的资源里有没有滚动条的规格，有就按它来。
   - 审查面板等其他滚动区域如果是同样的问题，列出来，本任务不改。
3. **底部间距**：
   - 消息流最后一行和输入框之间留出间距，按 Codex 的量。
   - 请求面板替换输入框时也一样。
   - 输入框的阴影不能压住内容。
   - 用 token 或现有的布局变量，不写死像素。
4. **用例**：
   - UNIT-stream-follow 补"发送后回到底部、恢复贴底""宿主开的回合不跳"。
   - 受影响的截图基线由 ui-baseline 重新生成，逐张给出原因。

**不做**：
- 出错卡片里 stderr 尾部太长的问题（留给 T148，已记在 T254 的汇报里）；
- client/presence 的上报（另立任务）。

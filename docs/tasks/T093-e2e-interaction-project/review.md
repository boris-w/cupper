## 修复第 1 轮：机器锁（编排者提出）

并行的 agent 直接跑 playwright，不经 CI 的机器锁，几个 e2e App 互相抢焦点、遮挡窗口，`@focus` 用例偶发失败。新增 `cargo xtask lock -- <命令>`：取与 `xtask ci` 同一个 `flock`，透传退出码；持锁运行的命令带 `CUPPER_MACHINE_LOCK=held`，嵌套时不再等锁；`xtask ci` 的持锁作业经 `JobCtx::command` 统一设置这个变量。`test:e2e`（两段）和新增的 `test:e2e:one` 都经这把锁运行。以后 e2e 一律经这两个入口或 `cargo xtask lock`，不再直接运行 `playwright test`。

## 修复第 2 轮：锁屏（用户决定 (b) 加 (c)）

- **(c) 防止显示器睡眠**：`test:e2e`、`test:e2e:one` 和 `xtask ci` 的 e2e 两段都套上 `caffeinate -d`，随命令结束、透传退出码，不留进程。
- **(b) 锁屏时明确报错**：globalSetup 开跑前经 `osascript -l JavaScript` 调 CoreGraphics（约 70 ms，不需要额外权限），锁屏、主显示器睡着、或本登录会话不在前台时，直接以屏幕原因失败。没锁的状态实测通过；锁屏状态没能在新代码上实测（要用户锁屏再解开），执行者在今晚锁屏期间用 `ioreg` 看到过同一个 `CGSSessionScreenIsLocked` 标记，编排者接受这份旁证，下次自然锁屏时留意它的表现。

## 就地修的三处缺陷

1. **请求面板的第一下点击落空**：面板在按下鼠标时激活并拿掉底部提示，变矮后按钮下移，松开时指针已不在按钮上，真实用户也会碰到。改为提示等这次点击结束后再拿掉。
2. **文本题点"提交"没有反应**：改为有输入时"提交"与 Enter 一样用它作答；顺带修了多选题附带的文字单独作为字符串发出、被宿主拒为"不符合字段"。
3. **`ci pr` 的 smoke 不分 `@focus`**：同时带两个标签的用例改为最后单 worker 跑。T092 也做了同样的修改，本任务先合并，T092 合并时只留一份。

## 逐项意见

1. 六个编号的用例全部用真实输入，并核对宿主写进 `host.db` 的 `interaction.resolved`，断言落在宿主而不只是界面。
2. 多选题用 `raw` 造 `elicitation/create`，"别处已处理"用暂扣页面的 `requestAnimationFrame` 复现，都只在用例里做，产品代码没有测试分支。
3. 拒绝成功的用例改为确定性时序（拒绝后 agent 再问一次，保证跟进在排队时到达），去掉了靠睡 2 s 的写法。
4. approve-enter-esc 留在 `pr` 和 `@smoke`（编排者裁定），`ci pr` 因此多约 40 s。

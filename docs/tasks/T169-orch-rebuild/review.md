## 逐项意见

1. **检查点作废时缺什么补什么**：`session.configured` 按行重建，项目配置是否加载按项目当前的信任与 `ignore_for_good` 决定，`confirmation_required` 留给守卫第一次检查重新判定；`session.capabilities` 只在会话连接过 agent 时从缓存补；`queue.updated` 在 `queue_version > 0` 时按行补、版本号不变。不整体重建，避免把重放回来的新状态盖成旧值。去掉了 T089 留下的"视图缺配置回内部错误"。
2. **准备阶段崩溃后重开第一个回合**：`initial_prompt_json` 不为空且没有回合时，载入后把第一条消息交还机器；启动时 `SessionManager::reopen` 主动载入这类会话，只等一次读（毫秒级），其余在各自的任务里跑。平时走这条路的会话是 0 个。
3. **重复重开的问题**（执行者开工时发现）：第一条消息检查没过、进了排队时，`initial_prompt_json` 原来不清空，载入时会再跑一次。改为某一步提交时第一条消息已不在暂挂里，就在同一事务里清空，有用例。旧库按 P-4 删掉重建，不写兼容代码。
4. **被中断回合里没结束的条目**先补写 `item.completed`，终态与协调器结束回合时的取值相同（工具调用和晚到输出 `abandoned`、执行类命令按 agent 的中断是否停命令标 `may_still_run`），没有新增协议取值。`may_still_run` 不因宿主重启会回收进程组就改成 `false`，理由成立：资源采样之后才起的命令，进程组可能没被记下。
5. **会话层的 `privileged.executed`**：`session/create` 切到 `full_access`、`interaction/respond` 选了特权选项各记一条，判定未通过或不是特权操作不记；动作和细节取 `policy/describe` 带上会话事实的结果，与原生确认框描述的内容同源；经 actor 已有的审计通道发给写入任务。`session/set_config` 留给 T141。

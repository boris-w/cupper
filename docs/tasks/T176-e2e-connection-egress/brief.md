## 范围

**做**（计划 T176 一行；设计 5.9.4 的安全一节、5.8 的本地认证、Q27）：
1. **原始协议客户端**（Node，放在 `tools/e2e/src/` 下）：能按帧格式（`u32 长度 | u8 类型 | 负载`）直接连宿主的 Unix 套接字，自己控制握手里出示的 `auth`。
2. **假宿主脚本**（Node）：占住 App 或 CLI 要连的套接字，记录对方发来了什么。
3. **E2E-SEC-fake-host**：假宿主占住套接字时，App 拒绝连接，不发令牌，不向它泄露任何密钥材料。
4. **E2E-SEC-cli-fake-host**：假宿主占住套接字时，CLI 拒绝连接。
5. **E2E-SEC-no-key-client**：
   - 没有密钥的客户端不能以 `desktop_ui` 接入，最多得到只读的 `cli` 身份；
   - 出示 `auth: dev_key` 但证明错误或缺失时，得到 `unauthenticated` 并被断开，不降级成只读。
6. **E2E-SEC-egress 与 Q27**（`nightly`）：
   - 用 T167 的 `sampleNetwork`，对 App 的整个进程树（含宿主、适配器）用 `nettop` 采样；
   - 先验证可行性：能否稳定采到整棵树。
   - 不可行就换方法（例如本地代理），在汇报里给出结论和实测数据，由编排者更新设计 5.9.4、关闭 Q27。
7. **网关上传缓冲的评估**（T029 的交接）：上传缓冲按哈希建条目，刚发第一片就超限或乱序的哈希会留下空条目，直到 `blob/put` 或断开。用原始协议客户端复现，评估要不要加"每连接未决上传数"的上限。要改代码、并且在计划 1.2 的上限内（单处不超过 100 行、不改接口）的，单独提交就地修；超出的在汇报里提出。

**不做**：窗口内的安全用例（T092）。

## 逐项意见

1. **原因：生产缺陷，不只是测试的问题**。
   - 停止时 `close_stdin` 丢掉连接句柄，适配器在 stdin 关闭后自己退出。`Wire::Exited` 到达时 `end()` 就结束了实例，SIGTERM、SIGKILL 的定时器被取消。
   - 结果：停止开始时记下的后代进程组一个信号也收不到，被 launchd 收养。
   - 真实时钟下，适配器在关 stdin 后的 3 s 内退出是常态，所以生产里几乎每次停止都会漏掉自成进程组的工具命令，正是 K21 要防的情况。
   - 用例里手动时钟让 SIGTERM 通常抢在退出之前，所以只在负载高时失败，每次留下一对 `sleep`。这和编排者在本机看到的成对残留完全对得上。
   - 编排者在任务书里提醒过"不只是检查早了一点"，执行者没有停在加等待上，而是找到了根因。
2. **修复**：
   - 停止过程中适配器先退出、而 SIGTERM 还没发时，立即执行 `term()`，2 s 后 SIGKILL；
   - `end()` 在发过信号的组还有活着的成员时不结束；
   - 没有残留进程组时（常见情况）照旧立即结束。
   - 设计 5.6.8 的顺序不变，只是第 4 步不再被跳过。
3. **稳定复现**：新用例让时钟停在 SIGTERM 之前，适配器必然先退出；修复前 10/10 失败，修复后通过。自然失败率很低（500 次 0 失败），靠循环证明不了，补稳定复现是对的。
4. **测试不留残留**：
   - `Groups` 守卫按进程组号加启动时间记下整棵树，drop 时只杀仍是原组的组；
   - 记录写进临时目录，测试进程被直接杀掉时，下一次建守卫先清理；
   - `gone()` 给信号最多 5 s 生效。
   - 执行者用 `kill -9` 验证过被中断的情形。做法写进了 notes，后面的进程级用例照用。
5. **效果**：K21 的 4 条用例在并行负载下连跑 1,000 次 0 失败；跑完全部测试和 CI 后本 worktree 没有残留。

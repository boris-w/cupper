# T145 输入框增强 II：图片、斜杠命令、↑ 与发送键

- 派发日期：2026-11-04
- 执行者：子 agent（前端工程师，ui-core 与桌面）
- 分支：`feat/T145-composer-images-slash`
- 依赖：T142（已合并）。T148 依赖本任务

## 范围

**做**（计划 T145 一行；设计 5.7.4 输入框、5.7.7；PRD CP-1、CP-2、CP-3）：

1. **图片**：
   - 粘贴、拖入，或经"+"添加图片，作为 `image` 附件。附件条已能显示 `image`。
   - 拖放时显示覆盖层。
   - 内容经 host-client 的 `putBlob`（`blob/put`）上传，附件里放 blob 引用。
   - 图片的类型和大小限制以设计和协议为准，超出时给提示。
   - 拖入的文件：T142 目前一律按文件引用处理。图片要区分出来作为图片附件；其他文件仍按 T142 的规则生成文件引用。
2. **斜杠命令菜单**：
   - 命令来自能力（`available_commands`）。第一条消息发出之前，新会话页就能显示（AG-4）。
   - 菜单样式按 Codex：标题、搜索、最高 320 或 10 行。
   - 照 T142 的做法：从 `OverlayContext.area` 取文字区，加原生 keydown 监听，开头先判断 `keys.ts` 的 `composing()`。
   - 和 `@` 列表共用弹出层，同一时间只开一个。
3. **↑ 恢复**：输入框为空时按 ↑，恢复上一条发出的消息（Q39：按 PRD CP-1 照做）。组字时不触发。
4. **"发送快捷键"偏好**：
   - 可选 Enter 或 ⌘Enter，键是 `keys.ts` 里已有的 `SEND_KEY_PREF`，存在 prefs 里；
   - 设为 ⌘Enter 时，Enter 换行，运行中排队的键变为 ⌘⇧Enter；
   - 设置页的界面在 T147，本任务只做偏好的读写和按键行为。
   - 插话的按键归 T242（T140 之后）。这里只需保证 `keys.ts` 的结构便于 T242 加上插话，不提前做。
5. **用例**（都已登记）：
   - E2E-image-paste、E2E-slash-commands、E2E-send-key-setting；
   - 组件测试覆盖：菜单键盘、组字时不拦键、↑ 恢复、两种发送键。
   - 动到剪贴板、需要焦点或真实按键的用例标 `@focus`，只在 runner 上跑，本机不跑；其余按后台模式。
   - 有新截图时，基线只由 `ui-baseline` 生成。

**不做**：
- 设置页"通用"的界面（T147）；
- 插话的按键（T242）；
- 图片以外的二进制附件。
